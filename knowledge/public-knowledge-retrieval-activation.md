# K14：公共知识检索不以篇数启动向量层

> 状态：正式当前公共知识。
> 最近核验：2026-08-11。
> 适用对象：结构化中文技术 Markdown 知识包的公共检索；当前正式语料由 `knowledge/README.md` 列出的知识包组成。
> 环境：Windows 11；Python 词面／BM25 实现；Ollama `qwen3-embedding:8b` 全文向量；BM25＋向量等权 RRF。
> 版本边界：直接证据覆盖 K1–K12、22 条真实任务型查询，以及 50／100／200／400／800 篇、约 20%／40%／60% 改述的合成压力样本；真实语料和查询分布变化时必须重测。

## 回答的问题与价值门

公共知识包增至多少篇时应启动向量召回？结构化技术语料中，向量或等权融合是否已经比词面／BM25 显示稳定净增益？

检索层会影响后续 Agent 能否找到当前知识，也会引入构建、查询和维护成本。用篇数臆定启动时点会造成过早建设或继续漏检；本结论会在每次检索层复核和语料增长判断中重复使用，通过价值门。

## 可直接复用的结论

### 1. 当前真实知识包没有显示向量层的稳定净增益

[关联 #98（知识包检索召回对照）实验评论](https://github.com/Eridanus117/agent-control/issues/98#issuecomment-5259163307)以 K1–K11、22 条真实任务型查询（11 条词面重合、11 条改述）对照四臂：

| 方法 | hit@1 | hit@3 | 改述 hit@1 | 改述 hit@3 |
| --- | ---: | ---: | ---: | ---: |
| 词面 | 21/22 | 21/22 | 10/11 | 10/11 |
| BM25 | 21/22 | 21/22 | 10/11 | 10/11 |
| 向量 | 21/22 | 22/22 | 11/11 | 11/11 |
| 等权 RRF | 20/22 | 22/22 | 10/11 | 11/11 |

向量补回了一个改述型 top-3 漏检，却在共享术语密集的词面问题上损失一个 top-1；实际 RRF 又损失两个 top-1。这个样本支持“向量可能补充改述召回”，但没有显示相对便宜词法层的稳定整体净增益。

### 2. 50–800 篇合成压力样本没有出现可沿规模保持的拐点

[关联 #102（检索召回规模拐点）实验评论](https://github.com/Eridanus117/agent-control/issues/102#issuecomment-5259493468)把 K1–K12 与程序化合成干扰扩展到 50／100／200／400／800 篇，并在实际 16.7%／41.7%／58.3% 改述的三个平面运行 36 个轮换面板。预注册稳定门要求向量相对 BM25 的 hit@1 中位增益至少 5 个百分点、至少 80% 面板严格改善、hit@3 不退化，并且更大规模继续通过。

结果是：20% 与 40% 平面全档未过；约 60% 改述只有 200 篇单档通过，400 与 800 篇又因改善覆盖不足而未过。`>800` 只表示测试上界内未观察到拐点，不是对更大语料的预测。由此可以直接复用的结论是：**篇数本身不是向量层启动信号，当前 50–800 篇范围没有识别出稳定篇数阈值。**

### 3. 先等真实漏检，再用真实查询复核方法；不按篇数预建

当前路径保持 `knowledge/README.md` 入口与按需词面查找。只有自然任务出现经核验的 top-3 漏检，尤其是改述型问题未找到已存在知识时，才形成复核信号；复核应覆盖当时全部正式包，并至少比较词面／BM25、向量与实际融合，分列词面重合和改述查询的 hit@1／@3、耗时与退化。

一次真实漏检是启动**评估**的信号，不是启动向量产品的授权。向量层是否值得加入，取决于独立真实查询中对改述的可见增益、总体召回不退化和维护成本，而不是语料篇数、合成单档胜出或理想融合上限。

## 第一方来源与证据映射

1. [关联 #98（知识包检索召回对照）实验评论](https://github.com/Eridanus117/agent-control/issues/98#issuecomment-5259163307)：保存 K1–K11 查询集、四臂 hit@k、分型、耗时、逐条失误、复跑与限制；支持结论 1、3。
2. [关联 #102（检索召回规模拐点）实验评论](https://github.com/Eridanus117/agent-control/issues/102#issuecomment-5259493468)：保存 K1–K12、50–800 篇语料来源、三个改述平面、预注册稳定门、36 面板结果与合成边界；支持结论 2、3。
3. [`authority/01-knowledge.md`](../authority/01-knowledge.md) 的公共知识检索边界：当前已确认词法基线先行、向量层看改述查询的可见增益、日常先记录自然发现失败；本包提供当前实验数据与失效条件，不改变该权威。

两条实验在各自收口时都没有让“真实检索阈值”通过可信门：[#98](https://github.com/Eridanus117/agent-control/issues/98) 缺少独立查询与金标，[#102](https://github.com/Eridanus117/agent-control/issues/102) 又以合成语料为主。本包不推翻该判断，也不把方法排序或数值门升级为当前知识；它只准入两项与证据等宽的负结论——已测范围内没有稳定向量净增益，且篇数不能充当一个已经得到证据的启动阈值。真实阈值继续保持未知。

| 2. 可直接使用的结论和必要解释 | 通过 | 给出当前保持路径、真实漏检触发、复核对照面和不得由篇数推出启动的规则。 |
| 3. 第一方来源或可重复验证过程 | 通过 | 两条远端实验评论保存查询、语料来源、预注册门、结果表、耗时与复跑；方法可重复。 |
| 4. 对象、版本、环境和核验时间 | 通过 | 页首限定 K1–K12、语料档、改述比例、检索方法、环境与日期。 |
| 5. 例外、仍未知内容和不能推出的结论 | 通过 | 下节排除真实阈值、永久不用向量、其他语料形态及等权 RRF 的泛化。 |
| 6. 明确的失效条件 | 通过 | 下节列出自然漏检、语料形态、查询分布、模型与检索实现变化。 |
| 7. 下次最少复核步骤 | 通过 | 先记录一个自然漏检；只在信号出现后用当时全部包补一波真实查询，不重跑合成曲线。 |
| 8. 人容易理解、Agent 足以复用的表达 | 通过 | 中文正文以两个实验结论、当前动作和边界组织，表格保留决定所需的最少数字。 |

## 例外、未知和不能推出的结论

- 不能推出“永远不需要向量”。[#98](https://github.com/Eridanus117/agent-control/issues/98) 已观察到向量补回一条改述型漏检，说明语义召回可能在查询分布变化后产生净价值。
- [#98](https://github.com/Eridanus117/agent-control/issues/98) 的查询与金标由同一执行者构造；[#102](https://github.com/Eridanus117/agent-control/issues/102) 只有 12 个真实包，其余 788 篇为程序化合成干扰，且 36 个面板不是 36 组独立查询。两者不能给出真实生产分布的统计阈值。
- 50–800 篇无稳定拐点不能推出 800 篇以上会或不会出现拐点，也不能把 200 篇单档胜出写成启动门。
- 全文向量、`qwen3-embedding:8b` 与等权 RRF 只是本次实现；不能直接外推到分块、重排、调权、其他模型或平台原生语义检索。
- 当前结论针对结构化中文技术 Markdown。非结构化长文、图像／表格密集内容、跨语言语料或负责人私域知识均不在直接证据范围。
- “等待自然漏检”可能漏报检索失败；它是当前低成本触发信号，不证明所有失败都可观测。

## 失效条件

出现以下任一情况时，受影响结论停止直接复用并进入增量复核：

1. 自然任务出现经核验的 top-3 漏检，且目标知识在正式入口中存在；
2. 改述查询占比、非结构化内容占比、跨语言需求或同主题高相似包显著上升；
3. 语料不再以当前结构化技术 Markdown 为主，或正式包的组织和粒度明显变化；
4. 新的独立真实查询对照显示向量相对 BM25 在改述 hit@1 有稳定可见增益、总体 hit@3 不退化，且成本可接受；
5. 嵌入模型、分块、重排、融合或平台原生检索改变当前方法边界；
6. 当前公共知识检索权威或负责人已确认的启动门发生变化。

## 下次最少复核步骤

1. 日常只记录自然发现失败：查询原文、预期知识包、实际 top-3 与人工确认结果；没有真实漏检时不按篇数重跑。
2. 出现一条经核验的改述型 top-3 漏检后，建立一波覆盖当时全部正式包的真实任务查询；分列词面重合与改述，保留独立金标或独立复核。
3. 对同一查询集运行词面／BM25、当前可用向量与实际融合，比较 hit@1／@3、各分型退化、构建与查询耗时；预注册判据后再运行，不用结果倒推门槛。
4. 只有真实查询证据命中当时已确认的启动门，才提出产品动作；否则只更新本包的样本边界与未知，不重建完整合成规模曲线。

## 不适用范围

- 负责人私域知识的建仓、迁入、权限或 R1／R2 阶段验收；
- 向量数据库、托管检索服务、重排器或索引产品选型；
- 非结构化、多模态、跨语言与外部公开语料的通用检索结论；
- 自动记录漏检、常驻索引服务或检索层建设授权。
