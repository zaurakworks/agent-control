# K9：Agent 资源的六个观测面不可互相代替

> 状态：正式当前公共知识。
> 最近核验：2026-08-11。
> 适用对象：本机 Codex／Claude 账户、Session 与 Orca 运行资源的读数、解释和经营判断。
> 环境：Windows 11；核验时 Orca 1.4.177、Codex CLI 0.147.0、Claude Code 2.1.227、ccusage 20.0.19、resource-observability 0.2.0。
> 版本边界：工具字段和失败语义绑定上述环境；“不同对象与分母不可互换”是本包的核心边界。

## 回答的问题与价值门

账户已用百分比、Session 累计 Token、当前上下文剩余、API 价格、并发 Worker 数和验收交付数，能否互相换算或代替？一个读数为 `null` 时能否当作零？

资源快照会反复用于模型选择、并发波次、上下文压缩和负责人注意力判断。把不同分母的数量混用，会把累计处理量误当剩余上下文、把 API 价格误当订阅账单，或把并发数误当有用吞吐。本包提供可直接使用的读数边界，通过价值门。

## 可直接复用的结论

### 1. 先说明六个观测面，再解释数字

| 观测面 | 它回答的问题 | 不能推出 |
| --- | --- | --- |
| 瞬时上下文占用／压缩 | 当前会话窗口中还驻留多少内容 | Session 历史累计 Token、账户剩余额度 |
| 账户窗口／权益 | 某账户窗口当前大致使用多少、何时重置 | 某个 Session 的归因、处理速率或费用 |
| Session 累计 Token | 本地日志中该会话累计处理了多少 input／output／cache Token | 当前上下文剩余、账户余额或账单 |
| 货币账单 | 实际订阅、购买额度或按量计费发生了什么 | 不能由 API 公开价乘以本地 Token 自行推得 |
| 运行并发／终端资源 | 当前有哪些 Task、Dispatch 与 Worker 在运行或等待处置 | 最大并发能力、交付是否被验收 |
| 验收产出／负责人注意力 | 本波产生了多少可验收进展，发生了多少决定、纠偏与询问事件 | Token 数、并发数或额度利用率本身不构成有用吞吐 |

### 2. 来源、时间戳和未知值必须与数字一起传递

动态快照只回答观测时刻的状态。同一字段曾在同日出现对象、`null`、再次出现对象的序列，且返回原因未归因；跨时刻百分比的窗口与重置时间也可能变化。因此：

- `null`、字段缺失或 Provider 非正常状态一律记为“未知／不可用”，不写成零；
- 报告资源数字时附数据源、观测时间、字段名和窗口，跨时刻比较前先确认是同一窗口；
- 原因没有直接证据时保留未知，不用消耗、缓存或账户切换等猜测填空。

### 3. 当前工具只覆盖六个观测面中的一部分

在核验版本下，`orca account list --json` 读取账户窗口与部分权益；resource-observability 的会话回执读取 input、output、cache-create、cache-read 和 total Token。会话回执不包含当前 context window／used／left、压缩历史、账户窗口或货币费用；账户快照也不包含可归因到某个 Session 的实际账单。

本批实测中，某 Codex Session 累计 Token 约 4.08M，而同时上下文占用约 193K；这个差异直接证明两者分母不同，不应互相代替。

| 4. 对象、版本、环境和核验时间 | 通过 | 页首列明工具版本、Windows 环境与日期。 |
| 5. 例外、仍未知内容和不能推出的结论 | 通过 | 下节排除账单归因、最大容量、并发因果和固定比例外推。 |

## 例外、未知和不能推出的结论

- 账户百分比可能由多 Provider 使用面共享；当前工具不能把未归因变化分摊到某个 Session。
- 本包不知道当前订阅的实际货币账单、购买额度余额或自动充值状态；不用 API 价格代算。
- 本机的最大并发 Agent 数、Provider 同时执行上限、排队容量和降级阈值仍未知；“当前运行数”不是“最大容量”。
- 本批没有严格串行对照、逐 Worker Token 完整数据或统一价值归一化；因此波次数字不能单独证明并发造成吞吐提升。
- 4.08M 与 193K 是用来证明分母不同的当日样本，不是固定比例或当前资源读数。

## 失效条件

1. Orca、resource-observability 或 ccusage 改变字段、时间戳、未知值或账户／Session 边界；
2. Provider 公开说明改变上下文、缓存 Token、账户窗口或费用的计量关系；
3. 新工具开始直接返回可验证的上下文、实际账单、交付验收或注意力绑定，需重新绘制覆盖表；
4. 自然样本显示任意两个观测面已经在新协议中共用同一对象、分母和时间窗口。

## 下次最少复核步骤

1. 只读检查当前 `orca account list --json` 与 resource-observability 会话回执的 schema，核对是否仍分别处理账户窗口与 Session 累计 Token，并保留来源时间戳。
2. 核对会话回执是否仍不含 context window／used／left、压缩历史和货币字段；新增字段只更新对应观测面，不自动合并其他对象。
3. 下一张自然波次回执仍将验收交付与负责人注意力事件分列；若口径改变，只更新第六面的表达。

## 不适用范围

- 自动额度调度、自动模型切换或自动停止规则；
- 订阅结算、税务或 API 费用预测；
- 并发的因果 ROI 证明；
- 未核验的远程主机或第三方 Agent 平台。
