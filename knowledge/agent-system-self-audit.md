# K15：Agent 系统自审在一例中先于负责人纠偏发现方向缺陷

> 状态：正式当前公共知识。
> 最近核验：2026-08-12。
> 适用对象：Agent 主导建设、且会改变后续 Agent 行为、授权消费或共享工作流的高影响资产；不适用于普通低风险局部编辑。
> 环境：Windows 11；GitHub Issue 作为过程证据面；Orca 1.4.177 多 Session 协作；直接样本审计 `agent-control@2ce81eb` 与 `agent-plugins@176930a`。
> 证据上限：一例主动发起的真实多视角攻防审计及其后续负责人审批链，最多支持当前交付验收；没有重复自然样本、产品采用或长期收益证据。

## 回答的问题与价值门

Agent 建成一项高影响 Agent 系统资产后，主动审计自己的方向和机制，能否在负责人先指出问题以前发现实质缺陷？什么样的自审结果可以继续行动，什么结果必须停止并交还负责人？

高影响行为资产会被后续 Session 反复执行；若建造者把自己的假设同时带入实现和验收，错误可能沿授权、合同与安装面继续传播。这个问题会在入口、Skill、协作机制和长期工作流交付后重复出现，因此通过价值门。

## 可直接复用的结论

### 1. 已有一例直接证据表明，主动多视角自审能先于负责人纠偏发现方向缺陷

在[关联 #100（夜间新增资产的多视角攻防审计）](https://github.com/Eridanus117/agent-control/issues/100)中，协调 Session 主动把自己刚建设的三方审阅批准制等资产设为审计对象，并限定为只审不改。四个独立视角分别攻击一致性与守恒、可执行性、安全与回退、冗余与发现性；未参与第一轮的裁决者再逐项反证，把 19 项发现去重为 13 项，其中确认 10 项、存疑 1 项、驳回 2 项。

交叉裁决确认的两个高严重度方向缺陷是：

- C1：三方席位、角色凭证与决定回执不能形成同构身份链；协调者席真实依赖 Run 代际，受派评审席依赖 Task／Dispatch，而历史回执把两名评审的 Task 与评论反向绑定。
- C2：不同 Session 或模型只能证明执行来源不同；判定按公开顺序发布时，不能证明后票没有被先票锚定。

随后，协调 Session 在[关联 #44（规则只加不减的收敛实施）晨间专属事项](https://github.com/Eridanus117/agent-control/issues/44#issuecomment-5259434014)明确记录：该审计由自己主动发起，并据此暂停用三方制消费授权类和产品取舍类决定，把机制与授权边界交还负责人；未受缺陷影响、且已有独立合同的纯技术路径继续。这一来源链直接支持“本例中自审先发现并触发了正确的局部停止”，但不能推出所有自审都会成功。

### 2. 有效自审需要把“被审对象、攻击面和裁决”分开

本例可复用的最小形状是：

1. 冻结精确对象、版本和审计边界，先只读攻击，不让审计者边看边改写靶子。
2. 按真实风险拆分互不替代的视角；至少覆盖内部一致性、由新 Session 按文字执行的可行性、安全与回退、重复真相与可发现性。
3. 每个视角分别留下事实、推断、严重度、来源、最强反方、翻转条件、未运行项和建议处置。
4. 由未参与第一轮的裁决者逐项尝试反证、去重并标为确认、存疑或驳回；第一轮发现数不能直接当成缺陷数。
5. 只有裁决后的确认项才能驱动后续合同；存疑项进入负责人澄清，驳回项只保留为审计证据或证据上限。

同一个 Agent 单纯重读自己的方案，可以发现机械错误，却不能替代独立视角和交叉裁决；多视角数量也不是目标，关键是攻击面互补、来源可核验、裁决者与第一轮分离。

### 3. 自审发现缺陷不产生修复授权；停止范围应与被推翻假设对齐

本例中被推翻的是“三方审阅机制足以安全消费授权决定”这一前提，因此暂停的是依赖该前提的授权类和产品取舍类消费；纯技术缺陷仍按已有交付合同推进。可直接复用的处置顺序是：

```text
定位被推翻的前提
→ 暂停依赖该前提、共享其写入范围或会发布受影响结论的路径
→ 保留独立合同、独立所有权且不依赖该前提的安全路径
→ 机制、授权或产品边界问题交负责人；技术缺陷另立有界合同
```

审计成功只证明发现与分流发生了，不授权审计者修改授权本身、追认历史决定、扩大产品边界或把一次样本升级为长期机制。

## 两道准入门逐项判定

| 准入项 | 判定 | 依据 |
| --- | --- | --- |
| 价值门 | 通过 | 高影响 Agent 系统资产会被跨 Session 重复执行，方向缺陷若未被发现会沿合同和授权传播。 |
| 1. 明确回答的问题 | 通过 | 问题限定为主动自审能否先于负责人纠偏发现方向缺陷，以及发现后的停止边界。 |
| 2. 可直接使用的结论和必要解释 | 通过 | 给出一次已验证结果、五步审计形状和按被推翻前提冻结路径的处置顺序。 |
| 3. 第一方来源或可重复验证过程 | 通过 | 远端 Issue 保存四视角评论、独立交叉裁决、主动暂停回执和后续负责人决定。 |
| 4. 对象、版本、环境和核验时间 | 通过 | 页首限定被审提交、Orca 版本、Windows 环境、日期与过程证据面。 |
| 5. 例外、仍未知内容和不能推出的结论 | 通过 | 下节排除普遍有效性、长期收益、自动授权与普通低风险任务的泛化。 |
| 6. 明确的失效条件 | 通过 | 下节列出重复样本反证、审计形状变化、来源不可恢复和权威边界变化。 |
| 7. 下次最少复核步骤 | 通过 | 只需在下一项自然高影响自建资产中复查对象冻结、独立裁决、先于负责人纠偏和局部停止四项。 |
| 8. 人容易理解、Agent 足以复用的表达 | 通过 | 正文以已验证事实、执行形状、授权边界和最少复核组织，不要求还原终端上下文。 |

## 例外、未知和不能推出的结论

- 只有一例真实样本；不能推出多视角自审在不同模型、不同资产或长期运行中稳定降低缺陷率。
- 本例发生在负责人尚未指出 C1／C2 以前，但远端记录不能证明所有参与者不存在任何未记录的先验提示；可证明的是当前来源链中没有更早的负责人纠偏记录，且协调 Session 明确承担主动发起与暂停责任。
- 19 项第一轮发现中有合并和驳回；发现数量、严重度总和或 Agent 数量都不能代替交叉裁决质量。
- 本例证明的是当前交付验收，不是产品采用或长期依赖；负责人注意力、总周期与维护税的长期净收益仍未知。
- 自审不能自举权限。触及授权、产品目标、长期边界或负责人专属事项时，仍需当前合同所要求的负责人决定。
- 普通低风险、可回退的局部修改没有相同的预期损失，不应机械增加重型多 Session 攻防。

## 失效条件

出现以下任一情况时，受影响结论停止直接复用并先做增量复核：

1. 后续自然样本显示相同形状连续产生大量驳回项、遗漏负责人随后指出的核心缺陷，或协调成本高于被避免的返工；
2. 第一轮与交叉裁决不再由独立 Session 承担，或裁决者参与了被审资产的拆分和实现；
3. 审计对象、版本、来源评论或主动暂停回执无法从远端恢复；
4. 当前权威改变高影响资产的审查、负责人专属事项或路径冻结边界；
5. Agent 系统改用新的协作后端，而该后端不能证明独立执行来源、评论归属或交付顺序；
6. 新证据表明本例 C1／C2 的裁决或“主动发起、先于负责人纠偏”的来源链解释错误。

## 下次最少复核步骤

1. 只在下一项自然出现的高影响自建 Agent 系统资产上复核，不为证明本包而另造审计对象。
2. 开始前记录被审对象、精确版本、建造者、四类攻击面、只读边界和停止条件；第一轮结束前不修改靶子。
3. 核对每个视角是否分开事实与推断，并由未参与第一轮、也未参与实现的裁决者逐项反证和去重。
4. 记录负责人首次纠偏时间与自审发现时间；只有来源链明确支持时，才继续使用“先于负责人纠偏”的表述。
5. 若裁决确认方向缺陷，检查实际暂停范围是否只覆盖依赖被推翻前提的路径，并记录安全路径、负责人事项和后续合同；再比较返工减少与协调成本。

## 不适用范围

- 普通代码自测、格式检查、单 PR 当前 head 复审；
- 为满足流程而固定增加评审人数或审计轮次；
- 用自审替代负责人专属的授权、产品采用或长期依赖决定；
- 自动评分平台、常驻审计服务、周期调度器或离线唤醒的建设授权；
- 从一次成功发现推断 Agent 已具备普遍自主纠错能力。
