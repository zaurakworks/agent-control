# agent-prompt-design

## 流程
1. 恢复目标 Agent 合同：id、目标、非目标、触发条件、输入、输出、允许和禁止的能力、权威顺序以及验收证据。
2. 按持久层拆分内容：
   - 常驻 prompt：短不变量、角色、权威顺序、安全边界、路由义务和输出合同；
   - Skill：带触发条件、不适用边界、预期输出和退出条件的条件性多步骤工作流；
   - knowledge：带来源、版本、环境、例外和失效信号的可复用事实；
   - task state：当前进度和决定，绝不写入常驻 prompt。
3. 从能够完整定义预期行为的最小 prompt 开始。只有观察到歧义或失败模式时，才增加指令或少量典型示例。
4. Prompt 必须可操作：明确决定、负空间、事实来源和验证义务。避免口号、人格填充、重复流程、secret、隐藏默认和穷举边界列表。
5. 当前外部事实进入装配调研流程。只加入选定 profile 在项目内声明的能力。
6. 对声称的行为改善，使用 `agent-behavior-evaluation` 在等价条件下比较代表性场景。
7. 明确证据边界：文件存在属于声明态；lock/render 属于配置态；只有真实运行或客户端 probe 能支持实际生效态。

## 完成条件
只有当另一位审查者无需聊天历史即可识别 Agent 权威、必做和禁止行为、Skill 路由、输出合同和证据义务，并且所有改善结论均有可比较行为证据时，prompt 才算完成。
