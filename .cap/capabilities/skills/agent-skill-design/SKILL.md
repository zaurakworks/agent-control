# agent-skill-design

## 流程
1. 定义能力缺口、目标 Agent、正向触发、不适用边界、输入、输出、禁止行为、退出条件和可观察证明。
2. 编写标准发现元数据：
   - `name`：与父目录一致的小写连字符 id；
   - `description`：说明 Skill 做什么、何时使用，并提供足够的相邻职责边界以支持可靠路由。
3. `SKILL.md` 只保留常见工作流。分支细节放入一级项目内 reference，确定性操作放入 script，静态模板或数据放入 asset。
4. 自由度必须匹配风险：多种方案均有效时使用启发式；存在偏好形状时使用模板；一致性或安全脆弱时使用准确脚本或命令。
5. 写清决策点、必需输出、失败处理、验证循环和完成条件。不要复述模型常识，也不要通过 Skill 元数据授予未声明工具。
6. 只有当示例比文字更能说明路由或输出时，才加入少量典型示例。
7. 使用 `agent-behavior-evaluation` 设计正反激活场景，并验证所有行为改善结论。报告闭包前先验证元数据。

## 完成条件
只有当标准元数据通过验证、相邻路由边界可测试、条件上下文只在需要时披露、使用的每项能力都由选定 profile 授权，并且验收证据已报告时，Skill 才算完成。
