# agent-behavior-evaluation

## 流程
1. 写明目标行为、用户可观察成功条件、安全边界、评测客户端和不做事项。纯格式或元数据修复不得冒充行为改善。
2. 在修改前运行代表性任务建立基线；无法获得旧装配时，记录原因，不制造比较结论。
3. 平衡场景：同时包含行为应发生和不应发生的任务，并覆盖触发、输出、拒绝或退出、错误和状态层结论。
4. 保持 trial 可比较：记录客户端、可观察的模型、prompt 和 Skill inventory、工具面、输入、预算或停止条件、动作或 transcript、最终输出和相关环境终态。
5. 优先使用确定性结果检查；开放质量使用明确 rubric，必要时由人工校准。不要强制偶然的工具调用顺序，也不要接受 Agent 自述代替环境结果。
6. 对非确定性行为运行相称的重复 trial。分别报告首次成功能力和多次一致可靠性，不把单次成功泛化为稳定能力。
7. 每项结果标明它证明的是标准合规、声明态、配置态还是实际运行行为。没有真实客户端观察时，生效态保持 `unknown`。
8. 把真实失败转成回归场景；阅读失败 transcript，区分 Agent 错误、任务歧义、grader 缺陷和环境不稳定。

## 输出
- 评测目标和基线；
- 场景与成功条件；
- trial 条件和观察结果；
- 结果层级、限制和剩余未知；
- 是否支持改善、回归或仅配置变化的结论。

## 完成条件
只有当场景正反平衡、trial 条件可比较、结果检查面向可观察终态、结论限定在实际证据范围内，并且失败原因已审查时，行为评测才算完成。
