## 原始问题与期望结果

有价值的调研成果不能可靠进入后续任务，导致重复研究。

期望结果是：后续 Agent 先复用已经成立的成果，只补充变化与缺口，并使整理、复核和维护成本低于重复调研。

## 当前知识的定义

知识库不是调研材料堆积区，而是可信、仍适用、容易理解、足以直接复用的当前结论与必要内容集合。

“保存即可信”约束当前知识入口。原始材料、未证实推论、候选方案和失败实验可以留在任务证据区，但不以“低可信知识”或“待验证知识”等名字进入知识库。

Git 历史可以保留知识曾经是什么；历史版本不再代表当前知识，也不能未经重新核验就被检索为答案。

## 当前公共知识入口

当前唯一正式公共知识入口是 [`knowledge/README.md`](../knowledge/README.md)。只有该入口列出的当前包可以作为公共知识直接复用；`work/**`、历史、试用材料和未列入入口的候选仍只作为待核验证据。

## 两道准入门

进入当前知识必须同时通过价值门和可信门。

### 价值门

一条结论至少满足以下一项，才值得长期维护：

- 后续任务较可能再次使用；
- 正在更新或替换现有知识；
- 需要长期解释一个重要决定。

高成本调研必须保留任务证据，但已经发生的成本不能单独证明未来维护有收益。高成本只有与上述未来价值结合时，才会加强进入知识库的理由。

### 可信门

可信门按每条可复用结论独立判断；知识包只是容器。一条结论未通过，不阻止其他已经通过的结论进入同一个知识包。

每条当前知识必须同时具备：

1. 明确回答的问题；
2. 可以直接使用的结论和必要解释；
3. 第一方来源或别人可以重复的验证过程；
4. 对象、版本、环境和核验时间；
5. 例外、仍未知内容和不能推出的结论；
6. 明确的失效条件；
7. 下次最少复核步骤；
8. “人容易理解、Agent 足以复用”的表达。

“我们目前不知道某件事”可以成为可信结论，但必须说明已经核验的范围和依据。未经证实的猜测不能进入当前知识。

## 读取、复用和更新

出现以下任一情况时，Agent 必须先寻找范围匹配的当前知识：

- 准备进行多来源调研；
- 准备运行可重复实验；
- 结果将影响当前权威、Agent 配置或重要决定。

单次、低成本、不会沉淀为重要决定的事实查询可以直接完成。

```text
明确问题 → 找到范围匹配的当前知识 → 检查失效条件和核验时间
→ 直接复用仍成立的结论 → 只列变化、冲突和缺口
→ 只对这些部分做增量调研 → 形成更新候选
→ 每条结论重新通过两道门 → 替换当前知识
```

默认由执行任务的 Agent 完成读取、增量调研和准入检查。只有出现证据直接冲突、改变权威或重要决定、证据不足却必须行动、涉及私域或高损失风险时，才增加独立 Agent 或负责人判断。

如果无法按最少复核步骤确认某条结论仍然有效，该结论立即退出当前知识，重新核验前不能直接使用。旧内容只作为历史证据帮助复核。

结论通过两道门后，由执行 Agent 直接沉淀，不需要逐次等待负责人批准。

## 内容保存深度

知识包本身必须足以理解和使用结论，保存必要解释、关键证据、可重复步骤和来源，而不只保存摘要与链接。

默认不保存完整原始来源。只有来源难以再次取得，或复核必须依赖精确原文、原始配置或实验输入时，才保存必要的本地副本。

## 首个 MVP 边界

首个 MVP 继续使用“一项窄问题对应一个可信知识包”，先处理公共技术知识。

当前明确不做：

- 正式知识平台或知识图谱；
- 最终仓库数量、数据库、目录和技术栈决定；
- 自动抓取和保存所有调研内容；
- 多级可信度状态；
- 定时重做全部调研；
- 旧仓知识的整体吸收；
- 公共知识与工作电脑私域知识的混合设计。

工作电脑上的私域知识仍需要保存必要的完整内容，并可能需要结构化与权限边界；当前私人电脑没有私域样本，因此本轮不决定其具体形式，也不决定是否需要知识图谱。

## 已有证据与下一项证据

首个 K1“可信知识包”以 Codex `AGENTS.md` 与 Claude Code `CLAUDE.md` 的项目指令加载规则为主题。负责人阅读后确认它容易理解且足以复用；必要增量核验后，它已作为正式当前知识列入上述入口。

这还不能证明实际复用成本低于重新调研。下一次相关自然任务出现时，先读知识包，只补变化和缺口，并低成本记录：

- 是否找到范围匹配的当前知识；
- 哪些结论被直接复用；
- 补查了哪些变化、冲突和缺口；
- 可见时的近似耗时或 Token；
- 纠正、额外 Agent 检查和负责人介入；
- 读取、复核和更新知识包增加的工作。

不为验证而重跑一次完整调研作为对照。一次自然复用不能证明长期投入产出，但应足以决定继续试用、修改边界或停止。

## 后续最小行为实现

负责人随后明确批准并验收了 `knowledge-maintenance` `0.1.0`。它把上述规则收敛为一个条件触发的行为闭环：

1. 定位范围匹配的当前知识；
2. 检查失效条件并做最少复核；
3. 只列变化、冲突和缺口；
4. 只对这些部分增量核验；
5. 让每条候选结论分别通过价值门和可信门；
6. 按结果更新当前知识、退出失效结论，或只保留任务证据；
7. 在自然使用中记录足以判断投入产出的低成本数据。

独立复核曾发现初版没有明确规定“无法完成最少复核”时的处理；发布前已经修正为立即让相关结论退出当前知识。最终 Skill 已进入版本化的 `agent-plugins`，并安装到普通 Codex、Orca Codex 与 Claude。

这个 Skill 是知识维护行为，不是知识正文、知识仓或知识平台。它没有授权导入旧仓知识、建设知识图谱、决定私域知识结构或自动抓取全部调研材料。K1 的自然复用投入产出仍未知，继续按上一节的真实任务数据决定保留、修改或停止。

## 三层分工（过程层／蒸馏层／检索层）

**后续确认**：负责人于 2026-08-11 批准 9-D1（来源：[重构决定请求](https://github.com/Eridanus117/agent-control/issues/9#issuecomment-5255873360)、[决定回执](https://github.com/Eridanus117/agent-control/issues/9#issuecomment-5255912747)），确认知识领域按三层分工运转：

1. **过程层＝GitHub Issue**：保存调研与执行的过程记录、原始证据和中间判断。写入不设门槛，保存不等于可信；Issue 全文混有已被推翻的中间判断，其中的结论未经蒸馏不得当作当前知识直接复用。
2. **蒸馏层＝`knowledge/` 目录**：只保存从过程层蒸馏、并逐条同时通过价值门与可信门（见本文件「两道准入门」，可信门含八项要件）的可复用结论；进入即可信，复用前只做失效条件检查与最少复核。
3. **检索层＝两条并列边界**：公共知识检索与负责人私域知识检索分别受下节约束。公共当前知识仍只从 [`knowledge/README.md`](../knowledge/README.md) 发现；负责人私域知识有独立真源和受限建设路径，不因可被检索就进入蒸馏层或公共当前知识。

层间只有一条升级通道：过程层结论经两道准入门进入蒸馏层，没有旁路；蒸馏层结论失效时按既有规则退出为历史证据，不降格为“低可信知识”留存。蒸馏时机同批获批为任务收口的固定自查（9-D2）；明确 Issue 的执行者在收口前直接完成，不依赖另一个工作流承载。

### 检索层的两条并列边界

**后续重审确认**：负责人于 2026-08-11 批准 69-D5（来源：[重审方向](https://github.com/Eridanus117/agent-control/issues/69#issuecomment-5257186458)、[决定回执](https://github.com/Eridanus117/agent-control/issues/69#issuecomment-5257301492)）。Orrery 资产迁入的原翻转条件已经命中；检索层不再用一条统一的「当前不存在、不建设」描述公共知识与负责人私域知识，而按以下两条边界分别推进：

1. **公共知识检索**：边界不变。正式语料仍只包括 [`knowledge/README.md`](../knowledge/README.md) 列出的当前知识包；启动仍由 9-D3 的「真实查询集对照实验」判定。查询取自真实任务并区分词面重合与改述两型，对照含 BM25 词法基线；词法索引先行，向量层看改述查询占比与可见增益而非篇数。日常先记录自然发现失败，信号出现后才运行决定前复核；具体阈值仍待真实数据单独批准。在启动判定满足前，`knowledge/README.md` 入口表继续承担发现路径，本次重审不授权建设公共知识检索层。
2. **负责人私域知识检索**：负责人已批准 Orrery 迁出重建，因此进入受限建设候选。独立私有 Git 仓中的 Markdown 是唯一真源，域树与 frontmatter 是组织基线；Orrery 资产沿已批的 raw Markdown＋kb-note-v1 双通道迁入，前者守住完整真源，后者只作结构化投影与对账。BM25 类词法索引是首级，向量召回只在负责人真实查询中对改述型问题显示可见增益后叠加，并以 RRF 按秩融合。编译投影、词法索引、向量与融合所需元数据均为可从 Markdown 全量重建的派生物，不成为第二真源。具体建仓、迁入、索引实现与验收只按 [#46](https://github.com/Eridanus117/agent-control/issues/46) 的逐阶段合同推进；本节不授权托管向量服务、把私域内容放入公共仓，或跳过阶段门直接建设。

私域迁入不等于进入公共当前知识。私域材料中的可复用结论只有逐条同时通过价值门与可信门，并列入 `knowledge/README.md` 后，才升级为公共当前知识；两道准入门仍是唯一升级通道，不因私域仓、索引或检索命中而产生旁路。

**阶段门与翻转条件**：公共知识侧继续适用 9-D3；连续两波收口蒸馏零产出，或真实数据表明两级启动无可见差别时，仍按原决定重审投入。私域侧不再把「负责人启动 Orrery 迁入」列为未来条件——迁入已经启动；后续改由 [#46](https://github.com/Eridanus117/agent-control/issues/46) 各阶段合同和 R1／R2 证据门约束：R1 只在迁入验收后启动 BM25，并以篇数与 hash 对账、真实查询 hit@1／@3、构建与查询耗时验收；R2 必须按词面重合／改述分型，对照 BM25、向量与实际 RRF 融合的 hit@1／@3，只有改述查询出现可见增益才启动。R2 未过门时停留在 R1；平台原生私域语义检索若日后同时满足权限、可移植与证据要求，其具体实现再由 [#46](https://github.com/Eridanus117/agent-control/issues/46) 合同重审。

## Route B 教学系统（负责人个人学习）

**后续确认**：负责人于 2026-08-12 批准 174-D1／D2／D3（来源：[关联 #174（Route B 教学系统采纳）方案与实质留档](https://github.com/Eridanus117/agent-control/issues/174)、[决定回执](https://github.com/Eridanus117/agent-control/issues/174#issuecomment-5266865760)；设计研究见 关联 [#173（Route B 教学系统设计）](https://github.com/Eridanus117/agent-control/issues/173)）：Route B（个人学习与 KB 内容，关联 [#166](https://github.com/Eridanus117/agent-control/issues/166)）按教学系统运转，方向为「概念 DAG＋学习者状态＋间隔复习＋teach-back」，边界「薄图、厚资产」。六条当前规则：

1. **三层分离（A1）**：概念结构、教学资产、学习者状态分开维护；文件不等同概念，也不等同掌握状态。
2. **薄概念图（A2）**：`requires`（硬先修）是唯一门控 DAG；对比、关联等其他关系保留为非门控类型化边；不建设通用知识图谱作为首版依赖。
3. **默认教学循环（A3）**：检索旧知 → 单一增量 → worked example／练习 → 形成性反馈 → teach-back → mastery gate → 延迟复习。
4. **掌握证据（A4）**：「掌握」至少区分即时解释／应用与延迟保持；自报、阅读完成或单次答对不单独构成持久掌握。
5. **检索边界（A5）**：图与学习者状态先做 eligibility 硬筛，词法检索只在允许的教学资产内排序；概念数量本身不授权向量层，与本文件检索层 R1／R2 门一致。
6. **保留长文（A6）**：既有单篇学习文档作为可复用叙事资产继续存在，不要求按原子节点批量拆分。
