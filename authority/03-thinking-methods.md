## 思考方法摘要

> 沿革：本节由 [`00-map.md`](./00-map.md) 原“当前最小实现方向”的 M43 段按 [关联 #44（规则只加不减的收敛实施）总图索引化决定](https://github.com/Eridanus117/agent-control/issues/44#issuecomment-5258111511)迁入；搬迁时只置换承载位置。其末句“更低层的产品边界和实现仍未确认”已滞后于同文件的后续确认；现按 [关联 #90（M43 摘要水位修复）](https://github.com/Eridanus117/agent-control/issues/90)更新摘要水位，不改变下文已确认的边界。

**当前摘要**：思考模式与元方法领域建设的不是另一种具体思考方法，而是 Agent 管理“当前如何理解和解决问题”的上位能力。跨任务改进属于其闭环目标，但经验只能成为带证据的候选，不能绕过知识、Skill 或系统规则各自的准入。该领域与长程工作不是必须独立实现的产品；它定义应当如何发现、选择和改进做法，所产生的可纠偏行为体现在长程工作体验中。当前已确认 `adaptive-problem-solving` 是任务内的方法控制器，按需方法登记面提供候选，具体方法继续由独立 Skill、文档或工具承载；负责人已批准直接全量建设方法库，具体结构和内容仍由有界实施合同演进。方法进入登记面不等于它可信、应当默认触发、已获得产品采用或取得本次执行授权；完整边界见下文。

## 当前问题

用户或 Agent 都可能错误界定问题、选择错误方法，现有方法又容易被固定成流程。

## 期望结果

能够识别问题类型，比较、选择、组合、升级、降级或退出方法，并根据真实结果改进。

## 已确认的根概念

**共同确认**：当前要建设的不是另一种具体思考方法，而是 Agent 管理“当前如何理解和解决问题”的上位能力。具体思考方法是它可以比较、选择、组合、升级、降级或退出的工具。

这项确认替代了“只固化问题与期望结果”的旧状态，但不决定它是否应成为独立产品、Skill、仓库或自动化流程。

## 已确认的跨任务关系

**共同确认**：跨任务改进属于这项上位能力的闭环目标，但不意味着它直接拥有或自行修改知识、Skill 和系统规则。

它根据任务结果产生“值得保留或修改什么”的候选及证据；候选再分别通过知识、Skill 或系统规则各自的准入判断。只有通过后的内容才能作为当前有效资产影响未来任务，并在复用中继续接受检验。

## 已确认的领域关系

**共同确认**：“思考模式与元方法”保留为独立问题领域，用于定义系统应当如何发现、选择和改进做法；它所要实现的可纠偏行为体现在长程工作体验中；具体思考方法是可选资源。

问题领域与产品或组件边界不等同。这项确认不推出思考模式与元方法必须成为独立产品、组件、Skill 或仓库。

## 已确认的承载边界

> 迁移来源：以下跨域承载边界由 [`00-map.md`](./00-map.md) 按关联 [#181（常驻规则面分层收敛）](https://github.com/Eridanus117/agent-control/issues/181)机械迁入；总图只保留路由。

**共同确认**：问题领域不整体 Skill 化，只把其中可重复执行的行为 Skill 化。必须广泛、持续生效的短约束由系统提示词或项目指令承载；条件性、多步骤、可复用的工作流可以由 Skill 承载；知识内容、任务状态、研发记忆和工具能力保留各自职责，不能因为都服务于 Agent 就被塞进 Skill。

因此，思考模式、知识和多 Agent 协作都可能产生一个或多个 Skill，但不等于这些领域本身就是 Skill。确认这项边界不自动授权创建对应 Skill，也不决定最终 Plugin、仓库或工具结构。在本领域，特定条件下重新界定问题、比较、选择、切换、降级或退出方法的可重复步骤可以成为 Skill。

`self-improvement` 是第一个可长期复用的窄切片：它处理已观察到的漂移、纠正和行为改进，也能在多轮概念增加却没有减少关键未知、形成决定或可检验资产时主动暂停，以最小可逆资产让高层判断接受真实反馈。它不代表完整元方法能力已经实现，也不能替代当前任务的方法控制；问题求解诉求的当前满足判断由 [zaurakworks/agent-system#4](https://github.com/zaurakworks/agent-system/issues/4) 承载，方法库目标形态与全量建设决定保留在旧仓 [Eridanus117/agent-control#70](https://github.com/Eridanus117/agent-control/issues/70)。具体版本和安装水位属于当前 Plugin 清单与安装面，不由本权威固化。

## 当前方法边界

**共同确认**：`adaptive-problem-solving`（APS）是当前任务内的方法控制器。它恢复问题、识别主瓶颈、比较普通处理与方法介入，并负责选择、组合、升级、降级或退出方法；按需方法登记面只向它提供可发现的候选及其证据、成本、进入门与退出条件，不建立第二套控制器。

**共同确认**：负责人已经批准直接全量建设方法库；决定来源为旧仓 [Eridanus117/agent-control#70 的 70-D1 至 70-D3](https://github.com/Eridanus117/agent-control/issues/70)，当前诉求状态由 [zaurakworks/agent-system#4](https://github.com/zaurakworks/agent-system/issues/4) 承载。本权威只固化职责边界，不固化问题类型表、schema、度量方案或具体方法清单。

**共同确认**：方法被登记只表示可被发现，不表示它可信、应当默认触发、已经获得产品采用或取得本次执行授权。方法仍须遵守自身硬门；例如带有显式同意门的 `grilling`，即使分类命中也只能建议，不能自动启动。

**共同确认**：具体方法的可执行定义继续由独立 Skill、文档或工具承载；自然任务样本、决定与验证证据保存在对应 Issue 或任务记录；私域原文留在获准的私有载体。登记面只保存选择所需的索引与方法卡，不复制这些载体的正文，也不改变各自的准入与权限边界。

用户背景和用户提出的方法仍不自动成为正确方法；具体方法已经存在或进入登记面，也不能替代当前任务中的适用性判断。

**被替代的内容**：本节替代此前“人类决定边界、默认介入程度、验证信号和具体载体仍未确认”的整体悬置状态，也替代“当前实施不授权立即扩展方法库”的旧边界。新的确认只解决控制器、登记面、方法资产、证据与授权之间的职责关系，并记录全量方法库已经获批；具体结构和内容仍由实施合同演进，不反向固化为权威。确认来源为 [70-D3 调研段](https://github.com/Eridanus117/agent-control/issues/70#issuecomment-5257310955)、[70-D2／70-D3 决定回执](https://github.com/Eridanus117/agent-control/issues/70#issuecomment-5257501697)与 [70-D1 终选回执](https://github.com/Eridanus117/agent-control/issues/70#issuecomment-5257533842)。

## 后续确认的问题求解治理方向

负责人确认可以用“问题求解治理能力”更直接地表达本领域当前目标：Agent 不只是掌握具体方法，还要在任务中管理“当前正在解决什么问题、是否已经漂移、现有做法是否仍然合适，以及是否需要改变方法或执行条件”。

这项能力需要在关键节点主动回看当前问题和路径，而不是只在用户已经指出错误后纠偏。它与 `self-improvement` 的职责不同：关键节点检查服务于当前任务中的方向控制；`self-improvement` 服务于已经观察到的纠正、失败或抽象循环如何形成长期行为改进。

在这个对齐节点只确认了职责分离和关键节点检查方向。具体 Skill 在后续恢复早期方法关系、纠正过窄方案并获得负责人实施确认后形成，见下一节。

## `adaptive-problem-solving` 的当前职责

负责人指出，关键节点方向检查不能代表完整元方法；一切后续行动首先依赖明确问题、判断向哪里发力，并把 ROI、调研成本和资源运营纳入选择。负责人随后确认先把这套基础能力做成一个薄控制 Skill。

`adaptive-problem-solving` 当前承担：

- 恢复原始问题、期望结果、背景、假设、候选方案、约束与当前阶段；
- 识别当前主瓶颈和最值得减少的关键未知；
- 比较普通处理与方法介入的预期价值、思考成本、风险、可逆性和反馈速度；
- 在需求／问题建模、对齐与结构化问询、受限调研、攻防／反证、ROI／选项分析、最小实验六类初始路线中选择或组合，必要时先做受限的方法发现；
- 检查模型、推理强度、上下文、工具、环境和 Agent／Session 组合是否与任务匹配；
- 为当前阶段设置证据、成本、授权、停止和验收条件，再根据反馈继续、升级、降级、换路或退出。

关键节点检查只是进入和维持这条控制循环的机制。六类路线也不是六个新 Skill；已有合适能力时复用，没有时只运行必要的最小步骤。发现跨任务行为缺口后仍交给 `self-improvement`，不能在本 Skill 中直接扩张系统。

该职责已进入持久行为资产和真实入口；当前有效版本、提交与安装状态由 `agent-plugins` 的当前清单及实际安装面按需核验，本权威只承载职责、授权边界和失效条件。自然任务中的收益、误触发和判断成本仍需后续观察，不为证明效果建设独立评测平台。

**守恒律置换记录（P0-4／A3）**：被替代的承载位于本文件“已确认的承载边界”与原“`adaptive-problem-solving` 的后续最小实现”，其中把 `self-improvement 0.1.2`、`adaptive-problem-solving 0.1.0`、提交号和三端安装水位写入当前权威。新承载只保留两个行为资产的稳定职责和边界；易漂移的版本、提交与安装状态唯一交由当前 Plugin 清单和实际安装面核验，不改变这些能力已经进入持久入口的结论。

## 最小实验与最小完整交付的后续澄清

负责人在 [计划／实验 `agent-control#19`](https://github.com/Eridanus117/agent-control/issues/19) 中指出：此前 Agent 把“最小可逆资产”泛化为默认产品策略，导致每次只做局部补丁，却长期依赖负责人发现漂移、串联流程和重复批准。

当前确认：

- **最小实验**用于尽快验证关键未知，可以主动缩小范围；
- **产品交付**应覆盖已批准目标的最小完整能力，不能为了最小 diff 静默删除、延期或弱化能力；
- ROI 默认比较总周期中的负责人注意力、有用吞吐、重复恢复、等待、返工、维护和机会成本，不只比较单个 PR 的改动量；
- “完整”不表示无界扩张。授权、风险、停止条件和证据等级仍然生效，新的产品边界或高影响取舍仍由负责人决定。

这一澄清已写入联邦式项目入口，并由明确 Issue 的直接实施、验证与交付路径继续检验；验证前不声称它已经降低长期成本，也不因此自动把所有普通任务升级成多 Agent 或重型工作流。
