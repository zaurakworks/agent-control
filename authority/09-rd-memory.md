## 原总图研发记忆摘要（搬迁）

> 迁移来源：以下段落由 [`00-map.md`](./00-map.md) 原“当前最小实现方向”按 [关联 #44（规则只加不减的收敛实施）总图索引化决定](https://github.com/Eridanus117/agent-control/issues/44#issuecomment-5258111511)原文迁入；只置换承载位置。

**后续确认**：研发记忆采用原始记录与可读记录两层。它保存权威和当前状态无法完整承载、但后续纠偏与自我改进需要复查的过程；保存不等于可信、权威或授权。完整边界见 [`09-rd-memory.md`](./09-rd-memory.md)。

## 要解决的问题

当前权威能回答“现在确认了什么”，当前任务能回答“现在做到哪里”，但两者都不足以稳定保留：原始问题如何演变、Agent 为什么偏离、负责人怎样纠正、哪些方案为何被拒绝、实验观察怎样改变了方向，以及长期资产从什么证据产生。

这些过程如果只留在会话上下文或高度压缩的摘要中，后续 Agent 难以复查错误原因，也缺少形成知识、系统提示词或 Skill 改进候选的材料。

## 已确认的双层边界

研发记忆分为两层：

1. **原始记录层**：尽量保留会话、关键操作、实验输出和产物，默认不进入 Agent 上下文。它用于避免整理时遗漏，并在出现争议或需要核查时支持追溯。
2. **可读记录层**：按原始问题、明确表达的推演理由、纠正、决定、实验、未知和结果组织，并能追溯到原始记录。它供负责人复查，也供后续 Agent 在当前任务明确需要时读取。

只保存摘要已经在本 Session 中造成关键因果信息丢失；默认读取全部原始记录又会带来过高的阅读、维护和上下文成本。双层保存用于同时降低这两种损失。

## 与其他资产的边界

- 研发记忆不是当前权威；历史表达和候选方案不能反向改变当前方向。
- 研发记忆不是知识库；保存不等于可信，只有重新通过价值门和可信门的结论才能进入当前知识。
- 研发记忆不是当前任务状态；它不能恢复已经结束、暂停或尚未授权的工作。
- 研发记忆本身不改变 Agent 行为。只有通过各自准入并进入系统提示词或 Skill 的候选，才成为当前长期行为资产。
- 研发记录保存可复查的输入、理由、决定、证据和结果，不声称还原模型没有外显的内部思维过程。

## 当前没有决定

- 是否需要数据库、知识图谱、日志服务或独立产品；
- 是否自动导出会话、自动整理或自动提炼候选；
- 私域原始记录的权限、加密和保存位置；
- 所有任务是否都要建档；
- 研发记忆的长期保留期限和跨仓最终结构。

首个 MVP 继续使用版本化、可直接阅读的文件，由 Agent 在关键纠正、决定、实验、资产形成和交接时人工维护。是否升级自动化只根据真实使用成本和收益决定。
