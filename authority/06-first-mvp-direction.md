## 当前首个 MVP 方向

> 迁移来源：以下段落由 [`00-map.md`](./00-map.md) 原“当前首个 MVP 方向”按 [关联 #44（规则只加不减的收敛实施）总图索引化决定](https://github.com/Eridanus117/agent-control/issues/44#issuecomment-5258111511)原文迁入；只置换承载位置，本文件后续确认仍按原时间顺序限定早期悬置语句。

**共同确认**：首个 MVP 选择“最小防漂移闭环”，目标是让一次工作能够可靠经过：

```text
读取权威 → 建立任务约定 → 确认授权状态 → 自主推进或请求决定
→ 记录工作与证据 → 验收 → 提议更新权威、知识或方法
```

选择这个方向不取消知识、思考模式、协同协作或资源与运营诉求。它们继续保留，并在这个基础闭环产生真实数据后按 ROI 分阶段推进。

这项方向后来已经进入实施。当前实现采用版本化权威与行为资产、GitHub 持久合同、Orca 活跃运行面和按需 Skill 路由；相关边界分别由 [`04-collaboration.md`](./04-collaboration.md) 与 [`08-mvp-implementation-direction.md`](./08-mvp-implementation-direction.md) 唯一承载。当前证据止于“当前交付验收”，不能据此推出产品采用、长期依赖或漂移已经消失。

## 要解决的问题

本次 Session 已经多次出现对齐内容没有及时完整固化、局部工作压过原始诉求、暂停事项被普通确认错误恢复等情况。这说明在继续扩展知识、方法、协同或配置能力前，需要先保证权威和授权能可靠传递到实际工作。

## 为什么先做它

1. 它对应本次 Session 已反复观察到的真实失败；
2. 知识、思考模式、协同协作和资源运营都会依赖它；
3. 它可以先以人工或低自动化方式验证，便于观察真实收益和成本；
4. 如果规则成本过高，可以缩减或退出，不必先建设完整平台。

## 没有被取消的目标

- 知识复用与增量调研；
- 思考方法的选择、升级、降级和改进；
- 多 Agent、多 Session、跨供应商协作；
- 资源、额度、上下文和人的注意力运营；
- Codex / Claude 配置、Skills、Hooks、MCP、Plugins 和跨主机分发。

它们继续保留，但不因为被记录就自动进入当前 MVP。

## 已决定与仍待证据

实施前的悬置清单已经被后续逐项决定部分替代，不再作为当前未决清单。正式权威仓、Windows 入口、当前事实承载、协作后端职责、按需行为资产与自动化边界已有现行承载；后续具体行动仍须服从各自 Issue 合同与授权，不能由本页推出开放实施权。

当前仍待证据或决定的是：

- 自然任务中能否持续降低漂移、恢复、返工和负责人注意力成本；
- 当前组件是否应获得产品采用或成为长期依赖；
- 最终仓库数量与职责、永久平台选择，以及是否提高自动化程度；
- 现有窄交付以外的新能力边界、权限、实施计划与执行授权。
