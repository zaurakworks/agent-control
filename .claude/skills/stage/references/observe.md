5. **本次是观察阶段。**完成判据在下面，不要再去别处找。做完本阶段就停——不要在同一次运行里连做两个阶段，尤其不要自己执行完再自己验收。

# 观察阶段

产出物是**事实**，消费者是下一个阶段。

## 完成判据

**未知项被列全，不是被回答。**列不出成功条件本身就是要报告的事实。

## 规则

1. 只读命中当前任务的**最窄一组来源**。不为了完整而扩大读取面。
2. 产出必须含**未知清单**。这是本阶段的核心价值，不是附录。
3. 记录来源版本：Git HEAD、加载过的路径、关键入口文件的哈希。下一阶段要靠它判断证据是否过期。
4. 拿不到的信息标 `unknown`，不猜，也不用相邻信息替代。
5. **不做修复。**发现的问题写进事实，不顺手改——改了就不是观察了。

## 产出形状

1. 结论：一到两句
2. 事实表：每条带来源与证据等级
3. **未知清单**：每条注明为什么拿不到
4. 明确没做什么
5. 下一步该进哪个阶段，以及为什么

## 终端绑定

- 交付写成文件（默认 `./observe.md`），路径在最后一行给出。
- 涉及某个仓时先 `git status` 并记录；发现未提交改动就报告，不清理。
