# 提议阶段

产出物是**选项**，消费者是**人**。

## 完成判据

**人能用一句话消费。**读完还要重新组织问题才能回答，就是没做完。

## 规则

1. **一个问题，说一次。**不要把三个问题混在一段里。
2. 至多三个候选，每个**带代价**——不只带收益。只写收益等于没给选择。
3. **点名推荐哪一个**，并说明理由。
4. 写明所需回复的**确切形式**（例：回复「批准 A」或「保留 B」）。
5. 附范围、明确不做的事、可逆性与升级条件。
6. **能在授权内自己决定的就决定**，用一个从句说明，不要交给人选。为无差别的选项打扰人是浪费。

## 产出形状

1. 结论：一到两句，说清要决定的是什么
2. 各候选：形状、代价、可逆性
3. 推荐哪一个，为什么
4. 所需回复的确切写法
5. 明确不做的事
6. **运行面自述四行**——格式见 [`SKILL.md`](../SKILL.md) 的同名章节

## 反模式

- 开放式提问（「你觉得呢？」）
- 有选项但没有推荐
- 把已经决定过的事再问一遍
- 候选之间代价相同——那不是取舍，直接选

## 终端绑定

默认只读，本阶段不实施。交付写成文件（默认 `./propose.md`）并给出路径；同时把结论与选项直接输出，因为人会先看输出。
