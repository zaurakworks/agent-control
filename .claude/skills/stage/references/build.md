5. **本次是执行阶段。**完成判据在下面，不要再去别处找。做完本阶段就停——**尤其不要自己执行完再自己验收**。

# 执行阶段

产出物是**制品**，消费者是判定阶段或世界。

## 完成判据

自检通过，且**没有自称验收**。

## 规则

1. 只写当前任务点名的对象。范围外发现的问题**只报告，不顺手修**——顺手修会让改动来源不明。
2. 自检通过即可交付，但**不得自称验收**。「我测过了」不是验收。
3. 改变权威性内容时同时记录被替代的内容与新结论，不静默漂移。
4. 写之前先跑一次并发检查；发现同范围有其他活动作业就停下并升级。
5. GitHub 评论引用其他 Issue／PR 写「关联 #N（中文短题）」，不用任何关闭关键词——**「不关闭 #N」同样会触发关闭。**

## 产出形状

1. 结论：改了什么，一到两句
2. 变更清单：文件 + 每处的意图
3. 自检做了什么、结果如何
4. **明确没做什么**（范围外发现的问题列这里）
5. 下一步：要不要进判定阶段，判据是"制品会不会进入不可逆路径"

## 反模式

- 顺手修范围外的问题
- 把自检说成验收
- 只在输出里报告改动，不落文件
- 撞到权限拦截后换条路重试

## 终端绑定

交付是文件、commit 或 PR，终端输出不是交付。并发检查用 `git status`；涉及 multica 时用 `multica issue runs <id>`。

**收口是显式的**——终端没有 run 结束这种硬边界，你必须自己声明"到此为止"，并说明做完了什么、没做什么、下一责任人是谁。
