# Codex 与 Claude Code 的项目指令加载规则

> 状态：候选知识，位于试用工作区；不是正式知识。
> 可信状态：下列事实已通过 K1 最低门槛。
> 最后核验：2026-08-09。
> 主题范围：Codex 与 Claude Code 在项目或仓库中加载持久指令的方式。
> 人工检查：负责人确认容易理解，并且内容足以复用；尚未经过后续真实任务复用。

## 回答的问题

Codex 和 Claude Code 分别读取什么项目指令文件？一个同时支持两者的仓库，怎样以最低重复成本共享入口规则？

## 可直接复用的结论

### Codex

1. Codex 在开始工作前读取 `AGENTS.md`。
2. Codex 启动时建立一次指令链。项目范围通常从 Git 仓库根目录向当前工作目录查找，每个目录最多采用一个指令文件；更接近当前目录的内容排在后面，因此具有更具体的作用。
3. Codex 默认最多把 32 KiB 的项目指令加入合并后的提示内容。大型说明不应全部放入入口文件。

### Claude Code

1. Claude Code 在每个会话开始时读取项目 `CLAUDE.md`。项目文件可以位于 `./CLAUDE.md` 或 `./.claude/CLAUDE.md`。
2. Claude Code 默认读取 `CLAUDE.md`，不直接把 `AGENTS.md` 当作自己的项目指令文件。
3. `CLAUDE.md` 可以使用 `@AGENTS.md` 导入共同规则。Anthropic 官方文档专门推荐已有 `AGENTS.md` 的仓库使用这种方式，避免维护两套重复指令。
4. 在 Windows 上，用 `@AGENTS.md` 导入比符号链接更合适，因为创建符号链接可能需要管理员权限或开发者模式。
5. `CLAUDE.md` 和它导入的内容会进入会话上下文。官方建议保持文件具体、简洁，并以少于 200 行作为目标；拆成导入文件可以改善组织，但不会减少启动时进入上下文的内容。
6. `CLAUDE.md` 是提供给模型的上下文，不是强制配置。需要无条件阻止某项操作时，应使用权限或 Hook 等强制机制；本次 MVP 没有采用这些机制。

## 对 `agent-control` 的适用结论

- 仓库根目录保留一份很短的 `AGENTS.md`；
- `CLAUDE.md` 只写 `@AGENTS.md`，不复制共同规则；
- `AGENTS.md` 只负责导航到 `README.md`、权威总图和当前任务；
- 详细权威和任务内容按需读取，不塞进入口文件；
- 这些入口文件用于引导行为，不能被当作安全边界或“绝不漂移”的保证。

## 可复现实验证据

在 `agent-control` 创建后，一个没有继承原对话内容的只读 Codex 上下文从 `AGENTS.md` 开始，按仓库规定的读取路径正确恢复了总目标、当前任务、授权边界和下一步。

这只说明当前 Codex 检查成功，不能证明 Claude Code 已在本仓库完成同等运行检查，也不能证明未来每次都正确遵守指令。

## 失效条件

出现以下任一情况时，不应直接复用本知识包，需要重新核验相关来源：

1. Codex 或 Claude Code 升级后，入口文件没有按预期加载；
2. 官方文档修改了文件名、查找顺序、导入语法或大小限制；
3. 仓库改为从子目录启动，或引入嵌套、用户级、组织级指令；
4. 开始依赖这些文件强制安全边界或权限；
5. 需要支持 Claude Code 以外的 Claude 产品或 Codex 以外的执行环境。

## 下次复用时的最少核验

1. 打开上述两份官方页面；
2. 只检查 Codex 的 `AGENTS.md` 查找与大小限制，以及 Claude Code 的 `CLAUDE.md` 加载和 `@AGENTS.md` 导入部分；
3. 如果相关规则没有变化，继续使用本结论；
4. 如果有变化，只更新受影响结论；只有出现冲突或范围扩大时才重新开展更广调研。

## 不适用范围

- 全局 Agent 配置优化；
- Skill、Hook、MCP 或 Plugin 的选择；
- 多 Agent 调度；
- 私域知识保存；
- 其他产品的指令文件；
- 强制安全策略。
