## 怎么看这份排序

以下评分只用于早期比较，不是假装精确的财务数据：

- 目标价值：对总目标的直接贡献，1 最低、5 最高；
- 当前证据：现在已有多少真实问题或使用信号，1 最少、5 最多；
- 解锁作用：能否帮助其他能力继续建设，1 最低、5 最高；
- 建设成本：实现和维护投入，1 最低、5 最高；
- 人的成本：需要负责人理解、选择和持续监督的程度，1 最低、5 最高；
- 不确定性：需求或方案仍有多少未知，1 最低、5 最高。

不把这些数字机械相加。当前优先选择目标价值、证据和解锁作用高，而建设成本、人的成本和不确定性仍可控的事项。

## 已完成：最小跨 Session 交接

运行环境盘点和 Windows 用户级入口已经完成。下一步不是继续清理所有配置，而是把现有入口用于一个真实、范围很小的任务，确认新的 Session 能否低成本恢复目标、授权、边界和下一步。

### 包含

- 选择一个真实、可在一次小交接内完成的任务；
- 由当前 Session 把目标、授权、边界、证据和下一步写入当前任务；
- 从一个全新 Session 读取入口并继续；
- 只记录是否正确恢复、出现了什么人工纠正以及实际成本。

### 第一次真实试运行

任务约定先写入并提交，再启动一个全新、临时、只读的 Orca Codex Session。启动提示没有复述任务答案。新 Session 在 304.2 秒内没有输出报告，达到 5 分钟上限后被终止；没有自动重试，文件没有变化，token 用量未知。

第一次无输出试运行当时只证明预算停止条件有效，不能证明任务恢复成功或失败。负责人随后批准改用可观察的两阶段 Orca TUI 重试。

### Orca TUI 可观察重试

负责人随后批准改用 Orca 原生终端接口，并提高预算。新 TUI 在约 49 秒内正确恢复三份权威文件和阶段门，随后用约 223 秒完成独立复核；没有越界或修改文件。

这次证明最小交接路径可用，也暴露了成本：`gpt-5.6-sol xhigh` 加多次网页搜索让一个很小任务累计显示 481K 输入。当前停止纯交接实验，在下一项自然真实任务中复用并观察。

### 不包含

- 不实现自动调度、消息总线或完整工作流；
- 不为了测试而制造复杂任务；
- 不证明“漂移已经被消灭”；
- 不顺带清理所有配置警告；
- 不进入多任务并发。

## 推荐顺序

```text
继续使用人工防漂移闭环
→ Codex/Claude 运行环境与配置盘点
→ 选择并实施一个最小改进
→ 用一次真实跨 Session 交接验证
→ 再判断是否值得建设插件仓、GitHub 同步或更多自动化
```

知识包等待真实任务自然复用；思考方法和资源观测在上述工作暴露明确问题时，以最低成本加入，不单独扩张。

## 已决定：Windows 默认执行权限策略

受限调研确认负责人重视的“低打断”与沙箱边界不是同一个控制，也确认 Codex 存在无询问的工作区边界方案。但当前没有证据证明其收益高于兼容、绕行和判断成本。

负责人最终选择维持 Codex `never + danger-full-access` 与 Claude `bypassPermissions`，不执行试点、不修改配置。普通任务不逐次重新判断；只在发生实际事故、敏感资产或权限明显增加、无人值守规模扩大，或出现已证明无摩擦的新边界时重新评估。详细依据见 [`permission-strategy-research.md`](../permission-strategy-research.md)。

## 推荐下一项：当前权威的远程恢复

四领域重新排序后，最直接的缺口是 `agent-control` 仍只有本机副本。它承载当前权威、授权状态和防漂移闭环；丢失后，已经完成的 Agent 入口和跨 Session 交接都不能在另一台机器恢复。

负责人已批准并完成这一切片。实际 GitHub CLI 是 Winget 安装的 `2.97.0`，使用绝对路径和本仓局部凭据助手覆盖后，现有历史成功推送；全新临时克隆的提交、工作区清洁状态、三份入口文件 Git 对象与 README 路由均通过检查。

当前权威已经有远程恢复路径。负责人随后单独批准了 `grilling` 的最小双端启用：普通 Codex、Orca Codex 和 Claude Code 的安装与新会话发现检查均已通过，原 Orca Session 也已成功恢复并加载该 Skill。这不授权继续安装其他插件或建设完整方法系统。
