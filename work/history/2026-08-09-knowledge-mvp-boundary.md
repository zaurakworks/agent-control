# 当前任务：定义知识库 MVP 的产品边界

> 归档说明：本任务已于 2026-08-09 完成；归档内容不再授权后续行动。

> 状态：负责人已确认共同理解，权威已更新，本任务完成；没有活动中的后续实施授权。
> 授权日期：2026-08-09。

## 原始问题

正常调研和探索会产生可复用知识。怎样让后续 Agent 先使用可信的已有知识、再只做必要的增量调研，同时避免把错误、过时或未经确认的内容保存成“知识”？

工作电脑上的私域知识需要连内容一起保存，并可能需要结构化；当前私人电脑没有私域知识样本。是否需要知识图谱仍是开放问题。

## 本轮目标

形成一个容易理解、足以支持下一步选择的知识库 MVP 边界候选，只回答：

1. 什么内容值得进入知识库；
2. “保存即可信”需要什么最低准入门槛；
3. “读取已有知识 → 增量调研 → 审核更新”的最小闭环是什么；
4. 首个 MVP 明确不做什么。

## 明确边界

- 不读取旧仓、旧 Issue、旧知识库或旧需求作为需求来源；
- 不创建知识仓、数据库、知识图谱、Schema、Skill、Hook、MCP 或自动化；
- 不采集、迁移或模拟私域内容；
- 不先决定最终仓库数量和技术栈；
- 不把候选方案直接写成权威；
- 未经负责人再次确认，不调用 `grilling` 开始问询；
- 不为本轮单独开展大规模外部调研。若出现会改变产品边界的事实缺口，先提出受限调研范围和停止条件。

## 压力测试已确认决定

第一轮已经确认：

1. 可信门按每条可复用结论独立判断，知识包只是容器；
2. 默认由执行 Agent 自检，证据冲突、重要决定、私域或高损失风险才增加独立 Agent 或负责人；
3. 无法确认仍然有效的结论退出当前知识，重新核验前禁止直接使用。

这些决定已写入候选，但尚未升级为知识权威。

第二轮已经确认：

4. 准备进行多来源调研、可重复实验，或结果会影响权威、配置和重要决定时，必须先查知识库；单次低成本事实查询可以跳过；
5. 知识包自身必须足以理解和使用结论，保存必要内容与证据；默认不保存完整原始来源，只在难以再次取得或精确复核确有需要时保存必要副本。

第三轮用于确认首次沉淀触发条件和历史版本的可信身份。

第三轮已经确认：

6. 结论通过可信门，并且会再次使用、正在更新现有知识，或需要长期解释重要决定时，由执行 Agent 直接沉淀；
7. “保存即可信”约束当前知识入口；Git 历史可以保留旧版本，但旧版本不能未经重新核验就被检索为答案。

重新检查发现一处冲突：早期确认和候选价值门把“首次调研或验证成本高”单独视为保存信号，第三轮选择的沉淀条件没有包含它。下一轮只澄清高成本是否单独足以触发保存；不把 Agent 的解释冒充负责人决定。

第四轮已经确认：

8. 高成本调研必须保留任务证据，但高成本本身不能单独把内容升级为当前知识；还需要可能复用、更新现有知识，或长期解释重要决定之一。

先前冲突已经解决并写入候选。当前只剩 MVP 的最低投入产出证据需要决定；完成后停止继续扩展问题树。

第五轮已经确认：

9. 第一次自然复用只记录低成本可得的数据：匹配情况、直接复用内容、增量补查范围、可见的近似耗时或 Token、纠正与人工介入、知识包维护工作；不重跑完整调研做对照。

压力测试到此停止。继续追问将进入仓库、格式、检索实现、私域结构或自动化，超出本轮产品边界。在负责人最终确认前，没有修改知识权威，也没有开始实现。

## 最终确认与结果

负责人确认了压力测试后的完整共同理解。产品边界已经迁移到 [`../authority/01-knowledge.md`](../authority/01-knowledge.md)，候选文件只保留为工作记录。

`grilling` 在第一次真实使用中发现并解决了一个隐藏冲突：早期的“高成本调研应该保存”不能被直接解释为“高成本本身足以进入当前知识”。最终区分为：高成本任务证据必须保留；进入当前知识仍需未来价值和可信性。

本任务没有创建知识仓、数据库、知识图谱、私域结构或自动化。下一步回到四领域和能力事项做 ROI 选择，不沿知识实现细节自动下钻。
