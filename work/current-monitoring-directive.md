## 执行边界

1. **唯一协调者是运行前件。** 同一 Run 或同一巡检范围已有在线协调者时，新 Session 保持只读并加入现有协调或取得明确交接；本页的 `active: true` 不产生第二份协调权。调度权的当前持有者以 D9 租约文件（`%LOCALAPPDATA%\agent-control\scheduler-lease.json`）的 `session` 字段为准，不由本页判定。
2. **没有产能下限。** 任何“至少 N 个 Session”的表述均已被替代；补派逐项通过候选价值门，缺候选时如实报告，不以扩大范围或制造低价值任务填充。
3. **清理孤儿 worktree 不是开放删除授权。** 只有运行面能证明没有活动所有者或 Dispatch、交付已经远端持久化、Git 工作树干净且精确身份与连带影响均已核清时，才按当前 Orca 生命周期合同处置；任一证据缺失即保留并报告下一责任人，不强制删除。
4. **运行态不写回本页。** 当前数量、终端、Dispatch、资源百分比和清理进度都从运行面派生；本页只保存指令字段及其来源水位。
5. **不新增自动化。** 本口径不建设常驻调度器、Hook、Webhook 或离线唤醒；Session 退出后内存态循环仍会消失。**已实测**：2026-08-14 约 08:30–11:26Z 巡检 cron 静默停摆约 3 小时而无人发现，因此本页的 `active: true` 不得被读成“兜底一定在跑”。
