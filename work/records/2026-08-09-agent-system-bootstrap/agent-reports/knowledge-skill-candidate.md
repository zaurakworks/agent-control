# 知识维护行为 Skill 候选

> 状态：并行子任务候选报告，不是权威，不是正式 Skill。
> 日期：2026-08-09。
> 依据：`README.md`、`authority/00-map.md`、`work/current.md`、`authority/01-knowledge.md`。未使用旧仓、旧 Issue 或旧知识定义需求。

## 结论

值得形成一个最小、条件触发的知识维护行为 Skill 候选。它不等于知识库，也不保存知识正文；它只执行下面这条已确认行为链：

```text
明确问题 → 查找范围匹配的当前知识 → 检查失效条件与核验时间
→ 复用仍成立的结论 → 只列变化、冲突与缺口 → 增量核验
→ 每条候选结论分别通过价值门与可信门 → 更新当前知识或保留为任务证据
```

候选名可暂用 `knowledge-maintenance`。正式命名、Plugin 归属、仓库和安装方式都不是本报告结论。

官方 OpenAI 文档把反复使用的工作流列为 Skill 的适用对象；这只支持“可重复维护流程可以用 Skill 承载”的一般判断，不定义本系统的知识边界。本候选的具体边界仍完全来自当前权威。[OpenAI 官方用例页](https://learn.chatgpt.com/use-cases)

## 触发与不触发

建议把以下触发条件压缩进未来 Skill 的描述元数据，使 Agent 能在加载正文前判断是否调用：

### 触发

出现任一情况时调用：

1. 准备进行多来源调研；
2. 准备运行可重复实验；
3. 结果将影响当前权威、Agent 配置或重要决定；
4. 用户或当前任务明确要求复用、复核、更新或沉淀当前知识；
5. 任务发现某条正在使用的当前知识可能失效、与新证据冲突或缺少必要适用条件。

前三项直接继承当前知识权威。第四、五项只是让同一维护闭环能够被显式调用，并没有扩大哪些内容可以进入知识。

### 不触发

以下情况默认不调用：

- 单次、低成本、不会沉淀为重要决定的事实查询；
- 只是在保存会话、原始材料、失败实验、候选方案或未证实推论；这些属于任务证据或研发记忆；
- 仅因一次调研成本很高就想把结果升级为知识；历史成本不能代替价值门；
- 定时重做全部调研、自动抓取所有材料、整体吸收旧仓知识；
- 私域知识任务；其结构和权限边界尚未确认，本候选只覆盖当前公共技术知识 MVP；
- 仅仅需要修改系统提示词、任务状态或权威，但没有知识复用或维护行为；
- 已有明确的独立工作流只需要消费一条已核验事实，且不涉及失效检查、增量核验或知识更新。

不触发不代表可以绕过项目权威、来源要求或风险控制。

## 最小输入

Skill 只接收完成维护行为所需的输入，不把这些输入复制成 Skill 内置内容：

1. **明确问题**：本次需要回答的窄问题、对象和期望用途；
2. **范围上下文**：对象、版本、环境、核验时间，以及结果是否影响权威、配置或重要决定；
3. **当前知识入口**：本任务认可的当前知识位置或检索入口；最终仓库和目录尚未决定，所以必须作为外部输入；
4. **范围匹配的知识包**：若找到，则提供当前正文、失效条件和最少复核步骤；
5. **当前证据入口**：新来源、可重复验证结果，以及任务证据／研发记忆的可追溯位置；
6. **授权和风险边界**：当前任务允许读写的范围，以及是否涉及证据冲突、重要决定、私域或高损失风险。

如果没有可用的当前知识入口，Skill 仍可以完成“未找到范围匹配知识”和增量调研后的准入判断，但不能自行决定正式知识仓、目录或技术栈。

## 最小步骤

### 1. 固定问题与适用范围

- 用一句话写清需要复用或维护的窄问题；
- 记录对象、版本、环境、核验时间和用途；
- 检查是否真正命中触发条件；若未命中，退出 Skill 并返回原任务。

### 2. 查找当前知识

- 只查当前任务认可的知识入口，不把旧仓、历史版本或任务证据当成当前知识；
- 记录“找到范围匹配知识”或“未找到”；
- 找到多个候选时，按问题、对象、版本和环境筛选，不因为关键词相近就合并。

### 3. 复核仍可用性

对准备复用的每条结论：

- 检查失效条件、核验时间、对象、版本和环境；
- 执行该结论注明的最少复核步骤；
- 只有仍成立的结论可以直接复用；
- 如果无法按最少步骤确认，立即将该结论退出当前知识，重新核验前不得作为答案使用；历史内容只保留为复核证据。

### 4. 限定增量工作

- 明确列出已经复用的结论；
- 只列变化、证据冲突和未覆盖缺口；
- 只对这些部分调研或运行实验，不重做已经成立的全部工作；
- 调研方法、实验执行和来源获取由相应工具或其他工作流完成，本 Skill 不内置通用调研方法。

### 5. 逐条执行两道准入门

每条可复用候选独立判断，知识包只作容器。

**价值门**：至少满足一项：后续任务较可能再次使用；正在更新或替换现有知识；需要长期解释一个重要决定。

**可信门**：同时具备：

1. 明确回答的问题；
2. 可直接使用的结论和必要解释；
3. 第一方来源或别人可以重复的验证过程；
4. 对象、版本、环境和核验时间；
5. 例外、仍未知内容和不能推出的结论；
6. 明确失效条件；
7. 下次最少复核步骤；
8. 人容易理解、Agent 足以复用的表达。

“当前不知道”可以通过可信门，但必须说明已核验的范围和依据。猜测、原始材料和失败实验不能以低可信或待验证知识的名义进入当前知识。

### 6. 路由结果

- **两门都通过**：在现有授权和当前知识入口中直接新增或替换当前结论，并保留可追溯证据；不要求逐条等待负责人批准；
- **价值门未通过**：保留必要任务证据，不进入知识；
- **可信门未通过**：保留来源、实验和未知于任务证据／研发记忆，不进入知识；
- **旧结论失效或无法复核**：从当前知识退出，历史版本保留但不再作为当前答案；
- **出现升级条件**：证据直接冲突、会改变权威或重要决定、证据不足但必须行动、涉及私域或高损失风险时，才增加独立 Agent 或请求负责人判断。

### 7. 记录一次自然复用数据

在自然发生的相关任务中轻量记录：

- 是否找到范围匹配知识；
- 直接复用了哪些结论；
- 补查了哪些变化、冲突和缺口；
- 可见时的近似耗时或 Token；
- 纠正、额外 Agent 检查和负责人介入；
- 检索、复核和更新知识增加的工作。

不为了验证 Skill 而另做一次完整调研对照。

## 输出

一次运行最多产生四类清晰分离的输出：

1. **复用报告**：是否找到匹配知识、哪些结论仍有效并被直接复用、复核依据；
2. **增量清单**：变化、冲突、缺口以及只针对这些部分取得的新证据；
3. **逐条准入结果**：每条结论是新增、替换、退出还是拒绝进入知识，并说明价值门和可信门理由；
4. **资产写入或可审查补丁**：在已有知识入口和授权允许时更新当前知识；若入口或写权限不存在，只输出可审查候选，不擅自建立新知识结构。

此外附带一条轻量 ROI 记录，以及在命中升级条件时给出具体的冲突、缺失证据和所需决定。输出不把整段会话或完整原始来源复制进当前知识。

## 与其他资产的边界

### 与知识正文

- Skill 保存“怎样找、复核、增量研究、过门和更新”的行为；
- 知识正文保存已经通过两道门的当前结论、必要解释、适用范围、证据、失效条件和最少复核步骤；
- Skill 不内置领域事实、知识目录副本、历史答案或来源全文；知识变化不应要求发布新版 Skill；
- 一个知识包可容纳多条结论，但每条结论独立准入和退出。

### 与研发记忆和任务证据

- 会话、关键操作、原始材料、人的纠正、错误原因、备选方案、失败实验、未证实推论和未通过准入的候选保存在任务证据／研发记忆；
- 当前知识只保留足以直接理解和复用的已通过结论及必要证据；
- Skill 输出对证据位置的追溯链接，不把“已经被保存”误当成“已经可信”；
- 研发记忆可以产生未来知识候选，但必须重新运行两道门，不能自动晋升。

### 与系统提示词和项目指令

- 系统提示词或项目指令只承载必须广泛、持续生效的短约束，例如服从当前权威与授权、不能让知识反向改写权威；
- 条件触发、复核、增量调研、逐条准入和更新步骤留在 Skill；
- 未来 Skill 的描述元数据应包含最小触发条件，使 Agent 能主动选择它，不需要把完整流程复制进系统提示词；
- 当前没有证据表明还需新增系统提示词规则。若自然任务中反复漏触发，再把“一句触发提醒”作为独立行为修改候选，不由本报告直接实施。

### 与权威、任务状态和工具

- 权威决定什么结论和边界已经由负责人确认；知识只能服务当前工作，不能自行改变权威；
- 任务状态记录当前目标、授权、阶段和下一步，不进入知识正文或 Skill；
- 搜索、联网、文件读写、实验和多 Agent 通信是工具／运行环境能力，Skill 只规定何时和怎样使用，不假装提供这些能力。

## ROI 判断

### 预期收益

- 避免对已经成立的结论重复做完整调研或实验；
- 让更新聚焦于变化、冲突和缺口；
- 减少过时结论、错误范围匹配和“保存即可信”造成的返工；
- 使知识更新行为跨 Agent、跨 Session 可重复并可审查。

### 主要成本与风险

- 每次命中触发条件都会增加检索、失效检查、准入判断和记录成本；
- 当前知识入口尚未最终确定，发现成本可能抵消收益；
- 失效条件或最少复核步骤写得差，会制造虚假的可信感；
- 过宽触发会把低成本查询流程化，过窄触发又会漏掉重要复用；
- Skill 不能验证自己是否真的比重做调研更便宜，也不能只凭 Agent 自述证明效果。

### 最小继续／修改／停止门槛

用下一次相关自然任务做一次低成本试用即可决定下一轮投资，不把一次结果当作长期证明：

- **继续试用**：找到范围匹配知识，至少直接复用一条仍成立结论，只补了变化或缺口，且检索、复核和更新的可见成本低于合理估计的重复调研；
- **修改候选**：知识有价值但难以找到、触发过早或过晚、字段或步骤导致明显无关工作、需要负责人纠正边界；
- **停止或降级为文档流程**：没有产生自然复用、维护成本持续不低于重做、反复导致错误复用，或只有单一 Agent／单一任务会使用而没有跨任务收益。

Token 额度充足不取消 ROI 门。主要判断是总体时间、纠错风险、维护负担和后续决策价值。

## 依赖与非依赖

### 正式化前的必要依赖

1. 至少一个当前认可的公共技术知识包和可定位入口；
2. 知识包能表达可信门要求的八项信息；
3. 任务证据／研发记忆存在可追溯位置，用于承接未通过准入的材料；
4. 执行 Agent 能访问必要来源或可重复验证环境，并能记录版本、环境和时间；
5. 当前任务提供读写授权；如只能读，则输出候选补丁而不擅自写入；
6. 正式发布时再决定跨 Codex／Claude 的 Plugin 打包、安装与触发一致性。

### 当前不需要

- 知识图谱、数据库、向量检索或正式知识平台；
- Hook、定时任务、自动抓取或全库定期重查；
- 多级可信度、待验证知识区或旧仓整体导入；
- 每次都启用独立 Agent；只有权威规定的升级条件命中时才增加检查；
- 独立评测平台或人为重跑完整调研作为对照。

## 最小实现切片建议

如果负责人之后批准正式化，首版只需要：

1. 一个包含上述触发／不触发条件的 Skill 描述；
2. 一份短 `SKILL.md`，实现“定位—复核—列缺口—增量核验—逐条过门—路由—记录自然复用”七步；
3. 一份逐条准入输出模板；
4. 使用现有 K1 可信知识包完成一次自然复用，不新增平台、索引器或自动化。

这是一项可逆的小资产：若首次自然复用证明发现成本、误触发或维护开销过高，可以修改或撤回 Skill，而不会改变知识正文、权威或工具结构。
