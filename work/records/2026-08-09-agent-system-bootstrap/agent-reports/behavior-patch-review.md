# `self-improvement` 0.1.1 行为补丁审查

> 审查时间：2026-08-09
> 审查范围：当前权威、`entrypoints/agent-system.md`、`self-improvement/SKILL.md`、Codex 与 Claude 两份 Plugin manifest
> 审查方式：只读审查；除本报告外未修改任何文件。

## 结论

当前补丁的方向与授权一致：系统提示词只增加主动触发信号，详细的“最小可逆资产”方法留在 Skill；Skill 明确要求 Agent 自己提出载体、检查授权、保持可逆，并在完成或推迟改进后返回原任务。两份 manifest 都已同步为 `0.1.1`。

发布前有 **1 个阻断项**：主动触发条件已经写入入口和 Skill 描述，但没有被明确接到原有的执行路径。这个缺口可能使 Agent 识别出抽象循环后仍依赖 Skill 自动路由或自行推断下一步，因而没有完全消除对用户纠正的隐性依赖。按下述最小修改补齐后，没有其他阻断项。

## 阻断项

### B1：主动触发与执行步骤之间存在条件断点

证据：

- 系统入口新增了“多轮讨论持续增加概念……”时主动按本节处理，但紧随其后的编号步骤仍以“当负责人指出……”为唯一显式入口；
- 入口第 4 步只在“纠正可能跨任务复用”时要求加载 `self-improvement`，没有明确覆盖“Agent 主动发现抽象循环且尚无用户纠正”的情况；
- Skill 的描述包含主动触发，但第一至第三节仍围绕“用户指出纠正”“保存纠正”“行为为什么没有改变”组织，没有说明无用户纠正时应如何进入第四节。

影响：Agent 可能只停下来检查，却不加载 Skill、不记录循环证据或不进入最小资产步骤；不同平台是否自动加载 Skill 还可能产生不一致。Skill 一旦被加载，其第九节能返回原任务，但在主动分支中“是否进入 Skill”尚不确定。

最小建议：

1. 在系统入口把两个条件合并成同一个编号流程入口，例如“当出现上述抽象循环信号，或负责人指出……时”；并将第 4 步改为“出现上述信号，或纠正可能跨任务复用时，加载可用的 `self-improvement` Skill”。
2. 在 Skill 第一节前增加一句主动分支说明：没有用户纠正时，不虚构纠正；改为重新锚定原始问题、当前关键未知、未取得进展的证据和被暂停路径，然后进入第四节。其他不适用的“纠正”记录步骤跳过或按循环证据记录。

这只需要少量文字调整，不扩大补丁范围，也不新增机制。

## 非阻断项

### N1：触发条件有有限的误触发风险

“多轮增加概念，但没有减少关键不确定性、形成决定或产出可检验资产”已经同时包含持续性和三个结果门槛，不会因一次普通错误立即触发。但在获准的发散探索、早期调研或方案空间扫描中，阶段目标本来就可能不是立即决策或产出原型，仍存在把正常探索判断为抽象循环的风险。

最小建议：把判断锚定到“当前阶段目标和停止条件”，或补一句“明确获准的发散探索在其停止条件内不因此触发”。这属于降低误触发成本的收紧，不阻断 0.1.1。

### N2：系统提示词与 Skill 没有形成不当重复

系统入口新增的是一条广泛生效的短触发规则；Skill 描述重复触发语义是为了可发现性，正文承载详细步骤。新增的最小资产流程没有复制到系统提示词。当前分工符合已确认的承载边界，无需为去重删除任一处触发。

### N3：自主性方向成立，但仍是人工规则而非可靠检测器

Skill 明确要求 Agent 主动提出载体，不等待负责人给实现答案；已有授权时直接实施，没有授权时只合并请求一次决定。因此它不再设计性地依赖用户提供方案。剩余局限是 Agent 需要自行判断“概念是否增加、关键未知是否减少”，这是当前人工 MVP 的可接受限制，不应在本补丁中扩张成 Hook、评测或路由器。

### N4：返回原任务和授权边界写得充分

- 系统入口第 5 步与 Skill 第九节都明确要求完成或推迟改进后返回原始任务；
- Skill 要求修改共享提示词或 Skill 前检查明确授权，无授权时请求一次决定；
- 最小资产不得因已实现自动升级为权威或最终架构；
- 补丁没有授权知识维护 Skill、多 Agent Skill、Hook、MCP、自动评测或复杂方法库。

除 B1 的主动入口断点外，没有发现返回原任务或越权方面的阻断问题。

### N5：版本元数据一致

Codex 与 Claude 的两个 manifest 均为 `0.1.1`，名称、描述、仓库和 Skill 路径一致。本次版本提升与行为变化匹配。

## 最小验收建议

补齐 B1 后做一次静态走读即可：分别从“负责人指出漂移”和“Agent 自己发现抽象循环”两个入口沿规则走到“最小资产／请求授权”，再走到“返回原任务”。本轮无需新增独立行为评测；后续真实任务出现相同信号时再观察是否实际触发。

### 静态走读 A：负责人纠偏

以“负责人指出一个会影响方向、且可能跨任务复用的漂移”为样例：

1. 系统入口的合并条件命中，先停止当前路径；
2. 第 2 步恢复原始问题、最近确认内容、被替代判断和当前授权；
3. 因本样例中的纠正会改变方向，第 3 步先把它写入当前任务；不会改变方向的一次性纠正不再被强制写入；
4. 因纠正可能跨任务复用，第 4 步明确加载 `self-improvement`；
5. Skill 第一至第三节再次校准必要信息、把纠正写入任务／获准的研发记忆，并用可观察证据诊断断点；
6. 如果纠偏针对的正是抽象循环，第四节直接形成最小可逆资产；其他可复用纠偏则经第五至第七节选择正确载体、判断长期收益并实施最小改进；
7. 第八节做与风险相称的检查，第九节明确交接并返回原始任务。

这条路径不再依赖负责人进一步提供实现答案。一次性、仅任务内且不会改变方向的普通纠正，可以不写当前任务、不加载 Skill，也不建立长期资产，这是入口第 3、4 步和 frontmatter 共同保留的成本边界，不是断点。一个纠正即使不改变当前方向，只要可能跨任务复用，仍会由第 4 步加载 Skill；若它改变后续行为，Skill 第二节会负责保存，因此收紧第 3 步不会使可复用纠偏丢失。

### 静态走读 B：Agent 主动发现抽象循环

1. 在未命中发散探索豁免时，系统入口第一句要求 Agent 主动处理；合并条件明确进入与负责人纠偏相同的编号流程；
2. 第 3 步保留主动循环的独立记录分支，明确记录关键未知与无进展证据；“只记录会改变方向的纠正”不会过滤该事件；
3. 第 4 步无条件覆盖该主动信号，明确加载 `self-improvement`；
4. Skill 第一节把主动入口列为独立入口，并要求记录原始问题、阶段目标与停止条件、关键未知、可观察的无进展证据和被暂停路径；
5. 第一节明确指向第二节保存“抽象循环事件”、第三节诊断循环原因、第四节形成最小可逆资产；
6. 第四节要求 Agent 自己选择载体，并以授权为实施边界；没有授权时合并为一次决定请求；
7. 完成或推迟后，第九节要求恢复原始问题和下一步并返回原任务。

原 B1 中“识别后是否进入 Skill、记录什么、如何到达最小资产”的三个不确定点均已消除。

### 发散探索豁免走读

明确获准的发散探索在其停止条件内，被系统入口和 Skill 第一节同时排除；达到或超过停止条件后，普通抽象循环判断重新适用。主路径不存在“先记录／改造、再发现其实被豁免”的明显断点。

剩余一个非阻断风险：Skill frontmatter 没有复述这项豁免，语义路由器仍可能在获准探索期间先加载 Skill；正文第一节会立即判定不触发，但没有单独写出“命中豁免后立即返回探索”的退出句。这最多造成一次无效加载或短暂停顿，不改变授权和资产，不足以阻断 0.1.2。若后续自然使用出现误触发，再把豁免压缩进 frontmatter，并补一条显式早退即可；当前不建议为此继续改版。

### 剩余非阻断风险

1. “概念是否持续增加、关键未知是否减少”仍依赖 Agent 的人工判断，当前没有独立检测器或自然任务数据；这符合人工 MVP 边界。
2. 停止条件如果过宽或不可观察，发散探索豁免可能延迟发现真实循环；应在具体任务约定中改善停止条件，不需要扩张本 Skill。
3. 系统入口先写当前任务，Skill 第二节又要求保存纠正，执行时应更新同一事件并按需补充研发记忆，避免重复记录；这是执行质量风险，不是流程断点。
4. Claude 的文件与缓存已更新，但已有 Claude 进程仍需重启或新 Session 才会应用 0.1.2；这是运行激活条件，不是发布内容缺陷。

### 发布判断

0.1.2 可以发布。原阻断项已由“合并两个入口、主动信号明确加载 Skill、无用户纠正时使用抽象循环事件记录”三处修复共同关闭；记录、Skill、最小资产、授权检查和返回原任务之间已有完整静态路径。入口第 3 步最终收紧只减少无方向影响的一次性记录，没有切断负责人纠偏或主动循环路径；**最终复查仍通过，没有新增阻断项。** 后续只需在自然任务中观察触发质量，不需要为本次发布新增行为评测。
