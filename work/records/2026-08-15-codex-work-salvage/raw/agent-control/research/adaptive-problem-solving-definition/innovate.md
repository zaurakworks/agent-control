# “自适应求解”能力边界候选

> 状态：已暂停的候选草稿，不是当前讨论顺序，也不是权威、实施计划或最终产品决定。`deep-innovate` 的多方案结构曾使分析过早进入方案比较；当前先回到原始问题，逐层对齐根概念。
> 输入：同目录 `research.md`、当前权威与负责人批准的概念综合范围。

## 需要定义的不是一种思考方法

原始问题不是缺少 `grilling`、苏格拉底式问询或产品设计等另一种方法，而是：

1. 任务中如何发现当前问题解释或处理方式可能不对；
2. 如何在继续、补信息、询问人、重新界定、改换／组合方法和停止之间作选择；
3. 如何不让这种“升级思考”默认变成高成本流程；
4. 任务后如何判断什么只是当次经验，什么值得进入知识、Skill 或系统规则的各自准入流程。

因此，候选定义的对象是“管理求解方式的上位能力”，而不是具体方法清单。

## 方案 A：单一双循环总能力

### 核心想法

使用一个统一名称“自适应求解与方法演化”，同时包含：

- 任务内循环：观察进展与证据，再继续、重新界定、调研、换方法、请求人决定或停止；
- 跨任务循环：根据后续效果保留、修改或淘汰方法。

### 优势

- 心智模型简单，直接对应“当下调整 + 长期学习”。
- 容易与长程工作的主委托体验结合。
- 不需要初期就把不同子能力分成多个产品。

### 风险与代价

- 一个“调整”同时指向计划、方法、问题解释和原始目标，容易越过人的决定权。
- 一个“保留”同时指向反思文本、事实知识、可执行技能和系统规则，容易绕过它们各自的可信门。
- 能力边界很大，Agent 可能在普通任务上频繁进入高成本分析。

### 与当前权威的适配

- 语义上覆盖 `authority/03-thinking-methods.md` 的全部期望结果。
- 对“总体低成本对齐”和“人工处理 → MVP → 自动化”的约束表达不够明显。

### 验证含义

需同时观察任务过程和后续复用。如果数据只能说明任务完成，就无法区分是当次方法有效，还是“方法演化”有效。

## 方案 B：单一体验、分层调控

### 核心想法

对用户仍呈现一项连续能力，但内在概念分为三层：

1. **任务执行层**：使用当前问题解释、方法和计划推进工作；
2. **求解调控层**：根据外部证据、人类反馈、不确定性和成本，决定继续、补信息、提议重新界定、改换／组合方法、升级／降级、请求人决定或停止；
3. **方法治理层**：任务后只产生经验候选和证据；候选是否进入知识、Skill 或规则，分别经过对应的准入与退出判断。

原始目标、价值取舍或权威边界的改变是横向人类决定边界：Agent 可以提出重新界定，不能把它自行当成新目标。

### 优势

- 把“做任务”、“改变做法”和“改变未来系统”分开，可以对各自使用不同证据。
- 保留了普通方法和升级思考之间双向切换，不把复杂流程设为默认。
- 不由“思考能力”直接管理知识和 Skill 存储，与已确认的知识可信门兼容。

### 风险与代价

- 三层区分增加概念负担；如果每个小动作都要先分层，就会产生用户担心的判断成本。
- “外部证据、不确定性和成本”仍然只是判断维度，尚未有通用阈值。
- 容易被误实现为固定状态机或强制每步评审，从而重新造成方法僵化。

### 与当前权威的适配

- 直接覆盖识别、比较、选择、组合、升级、降级和退出方法的期望。
- 人类决定边界与总目标中“不需要人判断时自主推进，需要时及时请求决定”相同。
- 调控层可以保持人工、轻量，只在真实数据支持时再逐步自动化。

### 验证含义

可分开观察：任务是否完成；调控介入是否让错误方向更早暴露、更容易恢复；一个经验候选后来是否真的通过准入并产生复用价值。

## 方案 C：拆成两项独立能力

### 核心想法

把问题拆成：

- **任务内求解调控**：作为长程工作的运行能力，只管当次任务中的监测、调整、对齐和停止；
- **跨任务方法治理**：作为独立的学习与资产治理能力，消化任务证据，再与知识、Skill 和系统规则的负责边界对接。

两者只通过“任务证据与经验候选”交接，不共用一个泛化的演化循环。

### 优势

- 当次任务和长期系统变更的责任边界最清晰。
- 可以只先验证任务内能力，不必同时建设方法库或演化系统。
- 跨任务学习失败不会直接改变正在运行的任务规则。

### 风险与代价

- 会把负责人原本感受到的一个连续能力切成两个概念，可能增加产品与仓库边界的讨论成本。
- 两项能力之间如果只传最终总结，容易丢失“当时为什么改方法”的证据。
- 分离后仍需要解决谁判断证据足以触发方法治理，并未消除判断成本。

### 与当前权威的适配

- 任务内部分可直接服务于“长程工作”；跨任务部分与“思考模式”、“知识”和未来 Plugin／Skill 治理都有交界。
- 最符合渐进投入原则，但不一定符合“先对齐完整概念，再决定 MVP”的理解方式。

### 验证含义

两项能力可分别验收，但还需观察交接是否丢失重要上下文、增加额外维护，或导致同一经验被重复判断。

## 显式比较

| 比较项 | A：单一双循环 | B：单一体验、分层调控 | C：两项独立能力 |
| --- | --- | --- | --- |
| 用户心智负担 | 最低 | 中等，外部可保持单一体验 | 最高 |
| 责任边界清晰度 | 最低 | 高 | 最高 |
| 初期误触发高成本思考的风险 | 高 | 中，取决于调控是否保持轻量 | 任务内可低，跨任务另行承担 |
| 绕过知识／Skill 各自准入的风险 | 高 | 低 | 最低 |
| 概念与实现过早绑定的风险 | 中 | 中；分层易被误读为状态机 | 高；容易过早导向多产品／多仓 |
| 分开验证局部价值 | 困难 | 较容易 | 最容易 |

## 领先候选：方案 B 的产品定义草案

> “领先”只表示它目前同时解释原始需求和调研反证的能力最强，不表示已选定。

### 一句话定义

**这是 Agent 系统管理“当前应怎样解决问题”的上位能力：它在任务中依据可观察证据、人类反馈、不确定性和成本，选择继续、补充信息、提议重新界定问题、改换或组合方法、升级或降级思考、请求人决定，或停止；任务后只提交有证据的经验候选，不自行把它升级为知识、Skill 或系统规则。**

### 它负责什么

- 维持对原始问题、当前解释、当前方法和当前证据的区分；
- 发现证据冲突、方向漂移、重复失败、边际收益降低或成本失控等需要重新选择的情况；
- 允许从普通处理升级到询问、受限调研或特定方法，也允许发现不值得后降级回普通处理；
- 区分当次纠错、问题重新界定提案和对未来系统的变更候选。

### 它不负责什么

- 不是另一种固定思考法，也不要求每个任务先执行完整方法选择仪式；
- 不自行改变负责人的原始目标、价值取舍、权威或已批准范围；
- 不把 Agent 自述的反思、信心或原因当作独立验证；
- 不默认开启大规模调研、多 Agent、多方法评审或长程反思；
- 不直接保存知识、安装 Skill 或修改系统规则；它只形成候选和证据。

### 成本原则

普通任务仍可直接执行。调控是轻量、持续的能力，而不是持续输出的分析文档；只有当预期改变决策的价值足以覆盖询问、调研、换方法或获取更多可观测数据的成本时，才升级。升级后发现价值不足，可以降级或退出。

## 关键假设

- Agent 至少能获得一些与任务结果相关的外部或人类信号；如果只有自我描述，调控的可靠性上限会很低。
- “提议重新界定”与“改变原始目标”可在权威上被区分。
- 知识、Skill 和系统规则的各自准入机制能够接收证据候选，不要求本能力同时承担全部资产治理。
- 早期可以用人工判断和现有 Agent 行为表达这项能力，不要求它首先成为独立自动化产品。

## 计划前需回答的开放问题

1. 对外是否把它定义为“思考模式与元方法”领域的一项独立能力，还是“长程工作”必须具备的横向属性；
2. 任务后的“方法治理”是本能力的第三层，还是只由它产生证据、再交给知识和 Skill 治理；
3. “重新界定”的人类决定边界是否可以固定为：Agent 可以自主修正不改变原始目标的工作假设；任何改变原始目标、价值取舍、权威或批准范围的重新界定都必须请负责人决定。
