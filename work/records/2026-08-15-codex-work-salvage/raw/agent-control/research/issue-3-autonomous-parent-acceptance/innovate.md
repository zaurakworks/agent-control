# Options Phase：自主父目标验收

## 方案 A：只改入口

核心是增加一条强触发，继续依赖现有 `adaptive-problem-solving` 和协作 Skill 自行推断详细检查。

- 优点：改动和版本成本最低；覆盖所有 Agent 系统任务。
- 风险：入口只负责触发，现有 Skill 没有能力回退、证据等级和 ROI 审阅面的闭环，容易再次“触发了但检查不完整”。
- 验证：只能证明新 Session 知道要加载 Skill，不能证明 Skill 提供了所需行为。

## 方案 B：入口 + `adaptive-problem-solving`

入口主动触发；通用 Skill 增加父目标贡献、能力回退、证据等级和可见 ROI。

- 优点：覆盖 PR 与非 PR 场景，职责清晰；只修改一个 Plugin。
- 风险：多 PR 场景仍由参与设计的协调者自我验收，保留本次已经观察到的同源盲区。
- 验证：可以静态走通普通父目标验收，但不能证明独立性。

## 方案 C：入口 + 通用检查 + 高价值协作独立父级复核

入口负责主动触发，`adaptive-problem-solving` 承载通用判断，`orchestrated-collaboration` 只补充高价值多 PR Agent 系统任务的独立复核路由。

- 优点：覆盖本次五个根因，同时保留普通任务轻路径；复用现有 Skill 和 Orca，不新增系统。
- 风险：横跨两仓、两个 Plugin 版本和三端安装；如果触发条件写宽，会增加协作与复核成本。
- 验证：分别做入口／Skill 静态走读、两个 PR 的提交后自审与独立复审，再做一次组合层父目标复核；安装后只做受限新 Session 复述，不复现旧失败。

## 方案 D：独立产品审查 Skill 或自动评测

将验收清单和执行器做成新 Skill、Hook 或平台。

- 优点：未来可扩展自动化和度量。
- 风险：当前只有一个清晰样本，新增路由、维护和观测成本高，超出授权；容易再次把建设系统本身当成目标。

## 比较结论

方案 C 是当前唯一同时覆盖广泛主动触发、通用问题求解闭环和多 PR 同源盲区的方案；它仍能通过窄触发和明确豁免控制成本。负责人已经批准该方向。A、B 留有已知断点，D 超出当前证据与边界。
