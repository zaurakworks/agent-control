# 研发记忆工作规则

`work/records/` 保存非权威、可追溯的研发过程。它补充 `authority/` 和 `work/current.md`，不取代两者。

## 最小结构

```text
work/records/<日期>-<主题>/
├── record.md
├── raw/
│   └── index.md
└── agent-reports/
```

- `record.md` 是默认可读入口，解释问题、纠正、决定、实验和资产之间的因果关系；
- `raw/index.md` 只登记原始材料的位置、保存状态、核对信息和限制；
- `agent-reports/` 保留并行 Agent 的独立报告，主 Agent 在 `record.md` 中记录采纳、拒绝和理由。

## 读取

新 Session 不遍历全部研发记忆。只有 `work/current.md` 明确链接，或当前工作需要复查某项决定、证据或资产来由时，才先读对应 `record.md`；需要解决争议或核对关键事实时，再按来源编号追到 `raw/index.md` 和原始材料。

当前权威与研发记忆冲突时，以当前权威为准。历史授权不能从研发记忆自动恢复。

## 维护

只在下列事件发生时更新：

- 原始问题、理解、授权或边界改变；
- 负责人作出会影响方向的纠正或决定；
- 方案被选择、拒绝或暂缓；
- 实验或新证据改变下一步；
- 形成长期资产、发生重要失败、交接或结束。

不记录普通读取、搜索、格式化和没有改变方向的工具调用。保存不等于可信、权威或授权；过程与结果相关也不等于方法有效。
