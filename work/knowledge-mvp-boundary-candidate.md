# 知识库 MVP 边界候选

> 状态：负责人已确认；权威内容已迁移到 [`../authority/01-knowledge.md`](../authority/01-knowledge.md)。本文件保留压力测试前后的完整候选，不作为后续授权入口。
> 依据：只使用当前知识权威和本次 Session 已确认的表达。
> 目的：让负责人判断产品边界是否对，再决定是否压力测试。

## 一句话定义

知识库不是调研材料堆积区，而是**可信、仍适用、容易理解、足以直接复用的当前结论与必要内容集合**。

这里的“保存”表示已经通过最低可信门槛。原始材料、尚未证实的推论、候选方案和失败实验可以留在当前任务的证据区，但不进入知识库。

Git 历史可以保留知识曾经是什么；“保存即可信”只约束当前知识入口。历史版本不再代表当前可信知识，也不能未经重新核验就被检索为答案。

## 1. 什么值得保存

先过价值门。满足以下任一条件，才值得支付整理和维护成本：

- 后续任务较可能再次遇到同一个问题；
- 结论会影响重要决定，即使复用次数不多也值得保留；
- 在未来工作电脑上，获准保存的私域内容是继续工作的必要依据。

高成本调研的任务证据必须保留，但已经发生的调研成本不能单独证明未来维护有收益。高成本只有与可能复用、更新现有知识或长期解释重要决定结合时，才会加强进入知识库的理由。

即使有价值，也不能直接保存；还必须通过下面的可信门。

结论同时通过价值门和可信门后，默认由执行 Agent 直接沉淀，不需要逐次等待负责人批准。主动沉淀信号包括：结论会再次使用、正在更新现有知识，或需要长期解释一个重要决定。

通常不保存：一次性低成本事实、完整聊天记录、没有明确用途的网页收藏、只因“以后也许有用”而收集的内容，以及无法判断适用范围的零散结论。

## 2. “保存即可信”的最低门槛

每条可复用结论都要独立通过可信门。知识包只是容器；一条结论没有通过，不阻止其他已经通过的结论进入知识包。未通过的内容仍留在任务证据区。

每条当前知识至少要同时满足：

1. **问题明确**：说明它回答什么，不把相邻问题混在一起；
2. **结论可直接使用**：保存明确结论和必要解释，而不只保存链接或搜索关键词；
3. **证据足够**：有第一方来源，或别人可以重复的验证过程；
4. **适用范围明确**：说明对象、版本、环境和核验时间；
5. **边界诚实**：例外、仍未知的内容和不能推出的结论写清楚；
6. **失效条件明确**：知道出现什么变化时不能继续直接使用；
7. **最少复核步骤明确**：下次不必重做全部调研，只检查最可能变化的部分；
8. **人能读懂，Agent 能复用**：表达通过“容易理解、足以复用”的检查。

“我们目前不知道某件事”也可以成为可信结论，但前提是已经明确核验范围和依据。未经证实的猜测本身不能进入知识库。

任何一项不满足，对应结论就留在任务证据区，不以“低可信知识”“待验证知识”等名字进入知识库。

## 3. 最小复用和更新闭环

不是所有外部查询都必须先查知识库。出现以下任一情况时，Agent 必须先寻找范围匹配的当前知识：

- 准备进行多来源调研；
- 准备运行可重复实验；
- 结果将影响当前权威、Agent 配置或重要决定。

单次、低成本、不会沉淀为重要决定的事实查询可以直接完成，不增加固定流程。

```text
明确当前问题
→ 找到范围匹配的当前知识
→ 检查失效条件和核验时间
→ 直接复用仍成立的部分
→ 只列出变化、冲突和缺口
→ 只对这些部分做增量调研或验证
→ 形成更新候选
→ 重新通过可信门后替换当前知识
```

默认由执行任务的 Agent 完成读取、增量调研和准入检查。只有出现以下情况，才增加第二个 Agent 或负责人判断：

- 新证据与当前知识直接冲突；
- 更新会改变已经确认的权威或重要决定；
- 证据不足，但任务仍要求据此行动；
- 涉及私域内容、权限边界或高损失风险。

如果更新候选不能通过可信门，当前知识不变。Agent 应在当前任务中说明缺了什么，而不是把不可信内容先保存进去。

如果读取时无法按最少复核步骤确认某条结论仍然有效，该结论立即退出“当前知识”，在重新核验通过以前不能直接用于回答或决定。原内容可以留在 Git 历史或任务证据区，帮助后续核验，但不再具有当前知识身份。

## 4. 首个 MVP 明确不做

- 不建设知识图谱；
- 不先决定最终仓库数量、数据库或技术栈；
- 不自动抓取和保存所有调研内容；
- 不把原始网页、完整对话或全部实验日志复制进知识库；
- 不建立多级“可信度状态”让 Agent 每次额外判断；
- 不允许“可能过时但仍可直接使用”的中间状态；
- 不自动定时重做所有调研；
- 不混合公共知识和工作电脑上的私域知识；
- 不吸收旧仓知识，除非新任务明确提出一个需要核验的问题；
- 不承诺知识永远正确，只承诺进入“当前知识”时已经通过门槛，并且有可执行的失效与复核规则。

## MVP 的最小产品对象

首个 MVP 继续使用“一项窄问题对应一个可信知识包”。每个知识包同时承载：

- 锚点：它是什么、回答什么、适用于哪里；
- 内容：可以直接复用的结论与必要解释；
- 证据和维护信息：为什么可信、何时核验、何时失效、下次最少检查什么。

知识包本身必须足以理解和使用结论。它保存必要解释、关键证据、可重复步骤和来源，而不是只保存摘要与链接。默认不保存完整原始来源；只有来源难以再次取得，或复核必须依赖精确原文、原始配置或实验输入时，才保存必要的本地副本。

这只是产品对象，不预先决定文件格式、目录、仓库或数据库结构。

## 当前仍需验证

- 下一次真实任务能否只补变化和缺口，而不是再次大规模调研；
- 整理、复核和维护知识包的成本，是否确实低于重复调研；
- 一个 Agent 完成准入检查是否足够可靠，哪些任务值得增加独立检查；
- 工作电脑上的私域内容需要怎样的结构、权限和完整内容保存方式。

这些问题不靠继续讨论全部解决。公共知识 MVP 应在下一次自然复用中记录实际成本；私域部分等真实环境和样本出现后再单独定义。

第一次自然复用只记录任务本来就能低成本提供的数据：

- 是否找到了范围匹配的当前知识；
- 哪些结论被直接复用；
- 只补查了哪些变化、冲突和缺口；
- 可见时记录近似耗时或 Token，不为补齐数字额外建设采集机制；
- 出现了几次纠正、额外 Agent 检查或负责人介入；
- 读取、复核和更新知识包增加了多少工作。

不为验证而重新运行一次完整调研作为对照。一次自然复用不能证明长期投入产出，但应足以决定继续试用、修改边界或停止。

## 候选结论

推荐接受这条边界：**知识库只保存已经可信的当前知识；每条可复用结论独立过门，调研过程与未通过门槛的内容留在任务证据区。默认由执行 Agent 自检，明确例外才升级检查；无法确认仍然有效的结论退出当前知识。是否值得保存与是否可信分开判断。先用窄知识包完成一次真实复用，以自然产生的轻量数据决定继续、修改或停止，再判断是否建设正式知识库。**
