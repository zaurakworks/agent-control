# 问安全网(ask-safety-net):遗留代码安全网的显式入口

**什么时候用我**:你在一个测试稀少的老 Java/Spring 仓上干活,凡是要动代码、写测试、评审 AI 产出而心里没底,就**按名问路**——对助手说「问安全网:<你要做的事>」(SKILL 形态用 `/ask-safety-net`)。我掌握下面的全目录,替你分诊,并给出明确下一步。不要指望助手干活干到一半自发想起该用哪张网——环境自动路由不可靠;问路是显式动作,像喊人名字一样便宜,养成习惯。

为什么需要安全网(三条底层判断,指导一切取舍):

1. 遗留代码的病根不是代码烂,是**改动无报警**:任何人(包括 AI)改错了,没有任何东西变红。所以第一优先级永远是"先有网,再动手"。
2. **地图补不了领土**:文档和注释机器查不了、跑不了,漂移了也不报警。知识压缩的正确介质是可执行物(测试/断言/lint 规则);文档只保留机器查不了的"为什么"(历史原因、取舍、外部约定)。
3. 测试自己也会说谎:实现者(尤其 AI)给自己的代码写测试是同脑自证。期望值要来自实现者之外,测试可信度要用突变测试度量。

## 使用协议(被问到时,按此应答)

1. 听清对方要做什么;信息不够先反问一句(改哪段代码?有没有测试?有没有生产日志?)。
2. 按分诊表选网;拿不准时最多给 2 个候选并说明取舍。
3. 应答固定给三样:**选了哪张网(技能名)→ 第一步具体做什么 → 去读哪份正文**。
4. 正文=`skills/<技能名>/SKILL.md`(单一真本):SKILL 形态用 `/<技能名>` 调用,文件形态(qodercli 等)直接按路径读该文件。
5. 分诊完成前不动手写代码;与红线冲突时先报红线。

## 全目录

| 技能名 | 一句话 | 你大概会这么问 |
| --- | --- | --- |
| characterization-tests | 特征测试:改老代码前先锁现状 | "要改一段没测试的老代码,不敢动" |
| log-replay-baseline | 日志重放:把生产日志蒸馏成回归基线 | "没有测试,但有生产日志" |
| example-first-oracle | 例子先行:期望值来自实现者之外 | "要实现一个新计费需求/新分支" |
| property-invariants | 性质不变量:不知精确答案也能抓错 | "没人说得清精确期望值,测试怎么写" |
| mutation-testing-gate | 突变测试门:用击杀率门槛裁决测试可信度 | "AI 交来一批测试,全绿,可信吗" |
| mistake-to-check | 犯错转检查:每个错误只犯一次 | "刚修完一个错,怎么保证不再犯" |
| kb 物化器(工具) | 坑卡双轨物化:`*.kb.md` 软链+`[KB]` 注释收割/注回+中央库快照 | "坑卡放哪,怎么跟着代码走"(用法见安装说明) |

## 分诊表

| 你正要做什么 | 先做什么 | 下一步读哪张网 |
| --- | --- | --- |
| 修改一段没有测试保护的老代码 | 先问"有没有网";没有→先锁现状再改 | characterization-tests;有可重放的生产日志→log-replay-baseline |
| 实现新需求/新计费分支 | 先向人要 5-10 个带期望值的具体例子 | example-first-oracle |
| 给算钱类核心逻辑写测试,没人说得清精确期望值 | 用领域性质+随机输入代替精确断言 | property-invariants |
| 刚收到一批测试(尤其 AI 写的),想知道可不可信 | 跑突变测试,按击杀率门槛裁决 | mutation-testing-gate |
| 刚修复一个错误(AI 或人犯的) | 把教训转成可执行检查或坑卡 | mistake-to-check |

## 红线(违反即停)

- 网没建好之前,不做"顺手重构",不删"看起来没用"的代码。
- 特征测试的期望值=现状输出,不判对错;例子测试的期望值=人给,AI 不得自己发明。
- 覆盖率不是目标,钉住即将要动的热点才是。
