# Agent 自我改进

把已经发生的纠正转成范围受限、可追溯、能影响后续行为的改进，然后返回原始任务。不要把自我改进本身变成新的无止境项目。

## 一、先停止并重新锚定

以下两种入口都要停止沿当前理解继续推演或实施：

- 用户指出方向、问题解释、优先级、授权或 Agent 行为发生偏差；
- 多轮讨论持续增加概念，却没有减少关键不确定性、形成决定或产出可检验资产。

已经明确获准的发散探索，在其停止条件内不因第二种信号触发。先恢复：

- 原始问题和期望结果；
- 用户刚刚纠正了什么，或当前仍未减少的关键未知是什么；
- 哪项旧判断已经被替代，或哪条路径应先暂停；
- 当前仍有效的授权、边界和下一步。

主动入口没有用户纠正时，不要虚构一条纠正。记录原始问题、当前阶段目标与停止条件、关键未知、没有取得进展的可观察证据和被暂停的路径；第二节按一次“抽象循环事件”保存，第三节诊断循环原因，然后进入第四节形成最小可逆资产。

### 停止的范围：只冻结受影响路径

“停止沿当前理解继续推演”指的是**依赖被推翻假设的那条路径**，不是当前所有工作。先回答：这次纠正推翻了哪一条假设？然后只冻结：

- 结论依赖那条假设的路径；
- 与之共享写入范围的路径；
- 会把受影响结论发布到远端、共享状态或用户可见面的动作。

有独立合同、独立写入所有权，且结论不依赖被推翻假设的工作继续进行，并记录这次判断。判断不清时，用“它会不会让一个错误结论进入远端或共享状态”来定。

只有当纠正指向的是全局不变量、授权本身或共享状态一致性时，才整体冻结。把独立、安全、有明确合同的工作一起停掉本身就是一次损失，需要和继续的风险同样被权衡。

不要要求用户重复已经表达清楚的内容。只有现有上下文和当前权威都不足以区分两种会显著改变结果的解释时，才询问一个最小问题。

## 二、先保存纠正，再继续展开

如果纠正改变任务方向、授权、问题解释或后续行为，应在继续前写入当前任务记录。若当前系统已有获准使用的研发记忆位置，同时写入可读记录并链接原始记录；若尚未建立该位置，只更新当前任务并明确缺口，不自行创建新的保存体系。

记录至少包括：

- 当时正在解决的问题；
- 出现偏差的判断或行为；
- 用户的纠正及其理由；
- 被替代的内容；
- 对当前下一步的影响。

保存不等于可信，也不让内容自动成为知识或权威。

## 三、诊断行为为什么没有改变

使用当前对话、任务记录和可观察结果定位主要断点。至少区分：

- 输入缺失：必要信息从未进入当前上下文；
- 状态丢失：已有决定没有被可靠恢复；
- 问题漂移：背景、方案或衍生诉求替代了原始问题；
- 提示词缺口：应始终成立的行为约束没有进入系统／项目指令；
- Skill 缺口：条件性、多步骤做法不存在、没有触发或步骤有误；
- 工具或运行环境缺口：Agent 知道怎么做但没有实际能力；
- 一次性错误：没有证据支持跨任务改造。

不要只用“上下文太长”或“模型忘了”解释。指出是哪一项信息、触发规则或行为步骤缺失，以及证据是什么。

## 四、用最小可逆资产打断抽象循环

高层建模不是长期停留在抽象层。如果连续讨论没有减少关键不确定性、形成决定或产生可核查资产，Agent 应主动选择一个能检验当前关键假设的最小产物：

```text
高层建模 → 最小可逆资产 → 真实反馈 → 修正高层模型
```

这个产物可以是一条短提示词规则、一个窄 Skill 切片、一份可读证据记录、一个受限实验或一个可丢弃原型。选择时要求：

- 直接检验当前最重要的未知或行为缺口；
- 修改范围小、容易审查、回滚和替换；
- 不因为已经实现就升级成权威或最终架构；
- 预期反馈足以影响下一步，成本不高于其决定价值。

Agent 必须根据问题性质主动提出载体，不等待负责人把实现答案反向提供给 Agent。若当前授权已经覆盖该最小产物，直接实施；否则把完整范围和主要副作用合并为一次决定请求。

### 这里的“最小”只指验证，不指交付

本节的最小可逆资产是**用来验证一个关键假设**的，它的完成判据是假设有了结论，因此允许缺完整性、鲁棒性和可发现性。

它不是**产品交付的最小完整闭环**。当本次要交付的是一项能力，而不是验证一个未知时，不能用本节的标准收口：闭环上任何一段必需能力都不能因为“改动更小”被砍掉。两者的完整判据表在 `adaptive-problem-solving`，本节不重复展开，只保留一条边界——用验证标准验收一次交付，会把能力回退伪装成节俭。

## 五、选择正确的承载位置

只把可执行行为 Skill 化，不把所有领域、内容或状态都塞进 Skill：

- 必须在广泛任务中始终遵守的短约束，进入系统提示词或项目指令；
- 只在特定条件下运行、包含多个步骤的可复用做法，进入 Skill；
- 关于“当前什么是真的”的可信结论，进入知识；
- 当前目标、授权、进度和下一步，进入任务状态；
- 原始讨论、实验和纠正证据，进入研发记忆或任务证据；
- 通信、并发、权限或外部操作能力，属于工具和运行环境，不由 Skill 假装提供。

系统提示词只留触发和不变量，详细步骤只放 Skill，不复制长流程。

## 六、判断是否值得形成长期改进

比较：

- 是否已经重复发生或可能在多个任务中复现；
- 影响是否足以改变方向、成本、风险或结果；
- 改动能否缩短为明确且不易误触发的规则；
- 新规则带来的上下文、判断、维护和误触发成本；
- 是否有更小的一次性修正。

收益不足时，只修正当前任务并保留证据。收益明显时，提出最小改进。不要因为已经花费了很多时间，就强迫系统长期维护它。

## 七、按授权实施最小改进

修改共享载体前绑定授权；缺少时一次说明范围和副作用并请求决定。

提示词／项目入口按授权最小实施并同步真实入口。承载位置是 Skill 时，把纠正、根因、目标行为和授权交给 `skill-maintenance`，消费其验证／审查结果；本 Skill 不复制维护协议，也不从旧仓、旧 Issue 或旧实现反推需求。

## 八、做与风险相称的检查

非 Skill 载体检查格式、差异和真实入口；Skill 载体使用 `skill-maintenance` 的结果。行为试验须有授权；不建设独立评测平台，后续真实任务再观察复发。

## 九、按需使用统一迭代回执

当前 Agent 系统任务已经登记一次迭代事件，或在自然里程碑需要跨 Session 恢复本轮因果时，读取 [`references/iteration-receipt.md`](./references/iteration-receipt.md)，在当前 Issue 的同一条自足评论中记录本轮证据。该 reference 只是一份证据格式：本 Skill 承载正文，不因此成为控制器、生命周期驱动者或统一状态库；普通一次性纠正也不为形式完整创建回执。

迭代事件的恢复、路线选择和证据等级仍由 `adaptive-problem-solving` 控制；本 Skill 只在纠正／抽象循环分支内回填实际产生的纠正、根因、被替代判断和行为载体，然后继续按本 Skill 的退出合同返回原始任务。

## 十、返回原始任务

完成或推迟改进后，明确交接：

- 原始问题；
- 本次纠正；
- 根因判断；
- 已修改或暂缓的载体；
- 当前应继续的下一步。

然后回到原始任务。除非自我改进本身就是当前获准的任务，否则不要继续扩张方法库、架构或自动化范围。
