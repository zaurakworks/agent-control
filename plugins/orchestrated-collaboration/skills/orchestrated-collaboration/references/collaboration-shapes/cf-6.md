# CF-6｜起草＋三方审阅一致制

## 身份与来源

- `shape_id`：`CF-6`；版本：`0.2.1`；维护者：协作域。
- 来源：[关联 #109（P0 三方审阅机制方案起草）方案](https://github.com/Eridanus117/agent-control/issues/109#issuecomment-5260729739)、[109-D1 三方审阅修订决定](https://github.com/Eridanus117/agent-control/issues/109#issuecomment-5260909104)与[关联 #100（夜间新增资产的多视角攻防审计）C1／C2](https://github.com/Eridanus117/agent-control/issues/100#issuecomment-5259393664)；许可／私域：自有，可移植；核验时间：2026-08-12。

## 目的与类型

- 要减少的未知／决定：替代授权内的决定能否获独立一致支持；类型：决定机制。

## 进入条件

- 先完整读取 `adaptive-problem-solving` 的 `references/pre-action-gates.md`；G2 证明真实阻塞且 G3 合格才进入，不复制判据。
- 可观察信号：已有替代授权且负责人点名；普通路径为负责人直接决定。
- C3=A：只覆盖已批合同内低风险、可逆的实施取舍与承载位置；产品采用、长期依赖、父目标满足、根诉求、授权变化、不可逆动作、真实支出及本规则变化仍归负责人。
- 输入：冻结的决定 ID、Issue、revision、选项、推荐、反方、翻转条件、C3 与包哈希；正文变化即换 revision／哈希。

## 硬门与禁用

- 明示同意：负责人明确授权；授权：起草／实施者不计票，三席至少一席异族，否决／存疑转负责人。
- 风险／写入所有权：协调者唯一消费；不适用：负责人专属类及身份、密封不可核验。

## 执行定义

### 机制一：席位身份联合类型

三席均审完整请求：R1「授权与边界」、R2「执行与身份」、R3「ROI 与维持现状」。

| 席位 | 稳定键 | 观察字段 | 只读来源 |
| --- | --- | --- | --- |
| 协调者席 | run_id＋consumer_generation | terminal、observed_at | run-show JSON |
| 受派评审席 | task_id＋dispatch_id | run_id、terminal、observed_at | worker-show JSON |
| GitHub 判定 | decision_id＋role_id＋comment_url | 作者、Issue、编辑水位 | 评论 API JSON |

- 默认三席来自独立 Dispatch；协调者回避且先密封时可替一席，否则只主持。
- terminal、Dispatch、Session 或人类身份须互异；发帖账号不替代运行身份。每票带包哈希、role、反方、模型族、密封 ID／哈希与判定。

### 机制二：机械映射

`<plugin-root>/scripts/verify-three-party-review.ts` 经 Orca／GitHub API 两轮只读取证，以稳定键连接并输出 JSON／R1→R3 表；不存凭据、不写状态、不发评论或消费决定。输入含目标、可信 User、模型族、终端排除表、三席身份、评论水位与密封字段；评论只许一个 `CF6-VERDICT-V1` 清单，密封载荷按键排序后算 SHA-256。

输出列为 `comment_url`、`role_id`、`seat_kind`、`stable_runtime_key`、`observed_terminal_handle`、`seal_message_id`、`seal_sha256`、`verdict`、`verified_at`；顺序固定。任一项使 `verified=false`：

- 非三席；role、URL、身份或 terminal 重复；起草／实施者入席；无异族模型席；
- URL／Issue／可信 User 错误；Task、Dispatch、Run、terminal 或评论清单任一键不一致；代际过期；两次取证变化；
- 包、公开载荷与密封哈希不一致；编辑水位旧；否决／存疑；工具、来源或远端未知。

### 机制三：先密封后公开

1. 冻结包并派三席；Task 写唯一 role、同一哈希和不同反方，Issue 暂无票。
2. 协调者占席须先向 Run 密封，再读 Delivery，否则无效。
3. 评审用本 Dispatch 的 `ask` 提交「判定＋理由＋反方回应＋翻转条件」；消息 ID 即密封 ID，超时恢复原消息。
4. 不转述各票；三封齐且预检通过后统一公开，再比载荷／哈希并两轮验证。

密封带时间戳、可哈希，公开前不进 Issue；不承诺密码学隔离。

### 机制四：状态机与时间盒

状态仅沿「请求冻结 → 三席派发 → 三封 → 统一公开 → 映射核验 → 可消费／仅证据」前进。限时 30 分钟；公开前可换一个失败席，再失败转负责人；公开后错位只作证据，不手抄修补。否决／存疑、代际变化或未知均转负责人。

- 步骤／执行资产：四机制与验证器；输出：密封、评论、映射与回执；完成条件：三票认可、硬门全过且 C3=A。

## 成本画像

- 墙钟：30 分钟；Token／工具调用：高；协调 Agent：三席；负责人问询：0 或失败时 1；维护成本：高。

## 风险与回退

- 主要失败方式：伪独立、锚定、错绑、假绿；可逆性：中；失败门：身份、密封、授权或来源不可核验；恢复路径：不消费，交负责人；公开后以新 revision 重做。

## 组合关系

- 前序：请求与替代授权；后序：CF-7；冲突：不与 CF-5 同审；最多组合深度：2。

## 控制规则

- 继续：三封齐且预检通过；降级：缺独立性走负责人；升级：只补改变判定的事实；换路：失败门转负责人；退出：回执或仅证据；翻转条件：再现错消费、连续三例假阳性、平均墙钟更高且未减问询、身份无法复读或先票可见改变判断。

## 有效性证据

- 来源等级：一手来源核验；能力证据等级：M0 静态实现；适用环境：已有 C3=A 授权的决定。
- 成功样本：无；失败样本：[关联 #90（M43 摘要水位滞后修复）反向绑定](https://github.com/Eridanus117/agent-control/issues/90#issuecomment-5258662798)须判失败；未知：自然样本与长期收益。

## 维护

- 失效条件：翻转条件或授权变化；下次最少复核：首个自然样本由未参评者复核；替代者：负责人直接决定、独立审查；选择级别：人工点名。
