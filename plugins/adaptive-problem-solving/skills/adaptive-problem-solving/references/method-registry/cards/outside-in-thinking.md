# 外部到内部分析

## 身份与来源
- `method_id`：`outside-in-thinking`；版本：`0.1.1`；维护者：agent-plugins。
- 来源：CIA《A Tradecraft Primer》Outside-In Thinking；许可／私域：公开一手来源的独立改写，未复制原文；核验时间：2026-08-11。

## 目的与类型
- 要减少的未知／决定：从外部力量、参与者与环境变化反推当前对象的约束和机会；主类型：P1；次类型：P4、P5。
- 预期效果：纠正只盯内部实现或当前仓库的局部最优。

## 进入条件
- 可观察信号：方案高度内部视角、外部依赖或用户行为可能决定结果；前置证据：对象边界与外部系统清单。
- 输入：参与者、制度／市场／技术／环境因素、时间范围；工具／上下文：必要时受限调研。

## 硬门与禁用
- 明示同意：无需；授权：外部分析不授权联系第三方或读取私域。风险／写入所有权：只读。
- 不适用：纯局部机械任务，或外部因素与成功条件无因果关系。

## 执行定义
- 步骤／执行资产：列外部力量与独立参与者，描述其激励和变化，映射到对象的约束、机会与脆弱点，找需要验证的最高影响链。
- 输出：外部因果图、关键约束与下一验证面；完成条件：至少一个外部因素能具体改变问题定义或方案。

## 成本画像
- 墙钟：20–60 分钟；Token／工具调用：中；协调 Agent：0–1；负责人问询：0；维护成本：中。

## 风险与回退
- 主要失败方式：宏观背景堆砌、未核验外部推断、范围失控；可逆性：高；失败门：因素无法连接到成功条件。
- 恢复路径：只保留一条最高影响外部依赖，转 P3 核验。

## 组合关系
- 前序：`aps-problem-modeling`；后序：`key-assumptions-check`、`alternative-futures`；冲突：无因果连接的背景扩张；最多组合深度：2。

## 控制规则
- 继续：外部因素会改变路径；降级：一个关键依赖；升级：多未来分叉转替代未来分析。
- 换路：缺事实转 P3；退出：外部约束进入问题合同；翻转条件：证据证明影响可忽略。

## 有效性证据
- 来源等级：本次直接验证＋一手来源核验；能力证据等级：M1 当前交付验收；适用环境：知识产品的外部使用方与运行环境约束分析。
- 成功样本：[关联 Eridanus117/agent-control#129（知识库真实复用率盘点）的实证评论](https://github.com/Eridanus117/agent-control/issues/129#issuecomment-5261790288)与[关联 Eridanus117/agent-control#130（知识库覆盖缺口盘点）的实证评论](https://github.com/Eridanus117/agent-control/issues/130#issuecomment-5262242274)；样本摘要：显式实战以“知识覆盖缺口应继续扩包还是先维护”为输入，从全新 Agent 最大使用方、负责人注意力、GitHub／Windows 宿主、Orca 版本变化与既有 Skill 载体反推约束。跨任务证据显示 K1–K16 中 9 包有真实使用、7 包严格零使用，六类真实摩擦中四类已有直接覆盖，同时 K5 的测试计数与 K2 的 Orca 版本水位已经失效；方法把方向从“按主题频次横向铺库”改为“优先维护新鲜度与正确载体，只保留 Windows 多行 Markdown 一个新增内容候选”。
- 失败样本：无系统记录；未知：本次属于跨任务材料上的事后卡片级复核，尚不能证明事前触发或跨领域迁移；证据上限为 M1，不支持 M2。

## 维护
- 失效条件：来源方法或外部环境水位改变；下次最少复核：下一次非知识产品的外部依赖分析后。
- 替代者：`aps-problem-modeling`；选择级别：APS 只可在知识产品的外部使用方与运行环境约束分析这一相同边界下建议。
