# Agent 自我改进闭环

## 身份与来源
- `method_id`：`self-improvement-loop`；版本：`0.1.0`；维护者：agent-plugins。
- 来源：仓内 `self-improvement` `0.1.3`；许可／私域：仓内自有，公开可移植；核验时间：2026-08-11。

## 目的与类型
- 要减少的未知／决定：把已发生的纠正、漂移、重复失误或抽象循环转成范围受限、可追溯的行为改进；主类型：P7；次类型：P1。
- 预期效果：纠正影响后续行为，并返回原始任务，不形成无界元项目。

## 进入条件
- 可观察信号：用户指出偏差／重复错误，要求沉淀经验，或讨论只增概念不减未知；前置证据：具体事件或可观察无进展信号。
- 输入：原始问题、纠正、被替代判断、授权；工具／上下文：当前任务状态与获准研发记忆。

## 硬门与禁用
- 明示同意：显式请求时已满足；主动抽象循环入口按 Skill 合同。授权：共享提示词／Skill 修改必须在任务授权内。
- 风险／写入所有权：只冻结受影响路径；不适用：普通一次性错误、偏好或任务内修复。

## 执行定义
- 步骤／执行资产：调用 `self-improvement` Skill；重锚定、保存事件、诊断断点、选择最小可逆资产、判断载体与长期价值、验证后返回。
- 输出：事件记录、根因、已改或暂缓载体与原任务下一步；完成条件：行为缺口有相称处理且原任务恢复。

## 成本画像
- 墙钟：20–90 分钟；Token／工具调用：中；协调 Agent：0–1；负责人问询：0–1；维护成本：中。

## 风险与回退
- 主要失败方式：一次性错误触发全套改造、最小实验冒充交付、整体冻结；可逆性：中高；失败门：改进不再减少复发风险或越过授权。
- 恢复路径：只保留任务内修正与证据，撤回长期资产候选，返回原任务。

## 组合关系
- 前序：任务纠正事件；后序：`aps-minimum-experiment`（仅验证未知）；冲突：无事件证据时与主动系统改造冲突；最多组合深度：2。

## 控制规则
- 继续：证据支持跨任务行为缺口；降级：只修当前任务；升级：共享长期行为修改需要新增授权时请求一次决定。
- 换路：根因是工具／环境转 P8；退出：改进处理完并回原任务；翻转条件：证据证明只是一次性错误。

## 有效性证据
- 来源等级：本次直接验证；能力证据等级：M0 实现完成；适用环境：Agent 系统纠正与行为改进。
- 成功样本：当前权威记录的两个范围受限行为补丁只证明资产可交付，不证明跨任务改进有效；失败样本：无系统记录；未知：跨任务复发率是否下降。

## 维护
- 失效条件：事件入口、只冻结受影响路径或载体边界改变；下次最少复核：每次可复用纠偏后核对。
- 替代者：任务内一次性修正；选择级别：M0；人工点名或 APS 明示“未验证”后建议，或系统入口明令的“多轮讨论持续增加概念，却没有减少关键不确定性、形成决定或产出可检验资产”抽象循环信号直接触发 `self-improvement` Skill；该入口授权不表示成熟度升级，其他 M0 场景仍不得默认触发。
