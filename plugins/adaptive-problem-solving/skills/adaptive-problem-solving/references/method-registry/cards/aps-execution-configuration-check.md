# APS 执行配置检查

## 身份与来源
- `method_id`：`aps-execution-configuration-check`；版本：`0.1.0`；维护者：agent-plugins。
- 来源：[APS 主合同](../../../SKILL.md)“配置执行并建立阶段合同”；许可／私域：仓内自有，公开可移植；核验时间：2026-08-11。

## 目的与类型
- 要减少的未知／决定：确认模型、推理强度、上下文、工具、环境与协作组合适合当前任务；主类型：P8；次类型：P3。
- 预期效果：把执行受阻与方向错误分开，避免靠加思考掩盖能力缺口。

## 进入条件
- 可观察信号：方案清楚但实施／诊断／验证受阻，或执行配置可能显著影响质量与成本；前置证据：当前任务难度与失败面。
- 输入：所需能力、可用配置、权限与工作区状态；工具／上下文：只读探针优先。

## 硬门与禁用
- 明示同意：无需；授权：不得擅自安装、改配置、读取凭据或扩大协作。风险／写入所有权：共享状态修改另过门。
- 不适用：真正瓶颈是问题解释或产品取舍。

## 执行定义
- 步骤／执行资产：逐项核对模型／推理、上下文、外部反馈、Agent 组合、权限与环境；只做足以改变下一步的探针。
- 输出：配置适配结论、限制、建议与下一动作；完成条件：阻塞被解除、准确路由或明确升级。

## 成本画像
- 墙钟：5–30 分钟；Token／工具调用：低至中；协调 Agent：0–1；负责人问询：0–1；维护成本：低。

## 风险与回退
- 主要失败方式：把配置切换当万能解、擅改宿主环境、无证据升级模型；可逆性：中高；失败门：探针需要超授权动作。
- 恢复路径：记录限制，保留只读路径，向协调者或负责人报告精确能力缺口。

## 组合关系
- 前序：普通诊断；后序：`aps-bounded-research`；冲突：用配置检查替代 P1／P2；最多组合深度：2。

## 控制规则
- 继续：探针会区分执行阻塞；降级：只核对一项关键能力；升级：确需新权限／工具时请求一次决定。
- 换路：方向假设错误转 P1／P3／P4；退出：阻塞解除或限制已路由；翻转条件：配置与失败无关。

## 有效性证据
- 来源等级：本次直接验证；能力证据等级：M0 实现完成；适用环境：工具与运行环境密集任务。
- 成功样本：尚无卡片级自然样本；失败样本：无系统记录；未知：减少无效重试的幅度。

## 维护
- 失效条件：APS 执行配置维度改变；下次最少复核：工具合同或协作后端变化时。
- 替代者：专业故障诊断；选择级别：人工点名或 APS 明示“未验证”后建议。
