# 关键假设检查

## 身份与来源
- `method_id`：`key-assumptions-check`；版本：`0.1.1`；维护者：agent-plugins。
- 来源：CIA《A Tradecraft Primer》关键假设检查；许可／私域：美国政府公开资料的能力级独立改写，未复制原文，具体版权以来源页为准；核验时间：2026-08-11。

## 目的与类型
- 要减少的未知／决定：找出结论依赖且未经证明的关键假设，评估其证据与脆弱性；主类型：P4；次类型：P3。
- 预期效果：把“默认前提”变成可验证、可翻转的显式对象。

## 进入条件
- 可观察信号：模型／方案已明确，但结论高度依赖少数前提；前置证据：当前结论、证据链和上下文边界。
- 输入：主张、支持理由、环境变化；工具／上下文：通常单 Session，必要时查一手来源。

## 硬门与禁用
- 明示同意：无需；授权：检查不授权实施或共享修改；风险／写入所有权：只读优先。
- 不适用：对象尚未形成、纯价值取舍，或所有前提都能低成本直接验证。

## 执行定义
- 步骤／执行资产：列结论所需前提，把证据状态区分为已知、部分、未知或冲突，分别评价结论敏感度、当前脆弱度与可观察失效信号，优先验证最脆弱且最关键者。
- 输出：关键假设表、验证优先级与翻转条件；完成条件：每个高敏感假设都有证据状态或下一验证面。

## 成本画像
- 墙钟：15–45 分钟；Token／工具调用：低至中；协调 Agent：0–1；负责人问询：0；维护成本：低。

## 风险与回退
- 主要失败方式：穷举无关前提、把未知直接判为假；可逆性：高；失败门：新增假设不再改变结论敏感度。
- 恢复路径：只保留最关键两项，转 P3 取证或普通路径。

## 组合关系
- 前序：`aps-problem-modeling`；后序：`analysis-of-competing-hypotheses`、`preregistered-experiment-card`；冲突：无明确结论时与全面检查冲突；最多组合深度：2。

## 控制规则
- 继续：假设会翻转决定；降级：只查最高敏感项；升级：来源冲突时转受限调研。
- 换路：多解释竞争转 ACH；退出：关键假设显式化；翻转条件：证据证明结论对该假设不敏感。

## 有效性证据
- 来源等级：本次直接验证＋一手来源核验；能力证据等级：M1 当前交付验收；适用环境：高影响模型、合同与方案。
- 成功样本：[关联 Eridanus117/agent-control#86（关键假设检查方法卡实战）的自然任务评论](https://github.com/Eridanus117/agent-control/issues/86#issuecomment-5258418149)；样本摘要：对真实夜间自治机制显式化 40 项隐含假设，发现巡检周期、角色资格、指令时间和 Session 身份四类高危信号，并将其收敛为可验证的 P0／P1 路径。
- 失败样本：无系统记录；未知：这些检查能否在首个机制消费和跨压缩巡检中稳定降低 Agent 方案误判。

## 维护
- 失效条件：来源方法或本系统 P4 边界改变；下次最少复核：首个机制消费或跨压缩巡检产生结果后。
- 替代者：`premortem`；选择级别：APS 只可在相同边界下建议。
