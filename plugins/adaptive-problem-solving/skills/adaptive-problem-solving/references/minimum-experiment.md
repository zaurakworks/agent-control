# 最小实验与完整交付边界

> 仅在 APS 已归型为 P6 并选择最小可逆实验，或验收时必须区分实验与产品交付时加载。收口后返回 `../SKILL.md`。

## 先声明是哪一种“最小”

| | 验证关键未知的最小实验 | 产品交付的最小完整闭环 |
| --- | --- | --- |
| 目的 | 让一个会改变方向的假设尽快被证实或证伪 | 让一项能力在真实使用中端到端可用 |
| 完成判据 | 假设有了结论，无论正反 | 用户或父目标能实际走完整条路径 |
| 允许缺什么 | 可以缺完整性、鲁棒性、可发现性 | 不能缺路径上任何一段必需能力 |
| 典型失败 | 为“做完”而扩张成半个产品 | 为 diff 小而砍掉闭环中的一段 |

不得用最小实验标准验收产品交付，也不得把一次实验升级成产品承诺；产品证据等级由 `milestone-acceptance.md` 判断。

## 预注册实验卡与收口卡

| 实验卡（开始前写死） | 收口卡（结束后填写） |
| --- | --- |
| 假设：〈做法〉会带来〈结果〉，观察到〈信号〉即证实 | 观察：实际发生了什么，与预注册判据逐条对照 |
| 检验方式与度量 | 结论：证实、证伪或仍未知 |
| 成功阈值 | 方向改变：改变了哪个决定或路径 |
| 停止条件与失效信号 | 遗留未知与下一步归属 |

成功判据在实验开始前登记；开始后只能作废重登，不能原地修改。解释结果前先排除测量或触发系统故障，再判断方法效果。实验卡是 APS 阶段合同在 P6 分支的具体化，不创建第二份任务状态。

只串联改变当前决定所需的少量方法，不为完整感全部运行。没有合适方法时执行当前必要的最小步骤；类别明显不足且方法选择会显著影响结果时，才做受限方法调研，不建设无边界目录。
