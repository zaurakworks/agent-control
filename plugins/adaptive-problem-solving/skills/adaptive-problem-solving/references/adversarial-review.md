# 攻防与多视角复核

> 仅在 APS 已归型为 P4 并选择轻量预演或重型攻防时加载。完成、对象被证伪或成本超门后返回 `../SKILL.md`；本文件是该分支的唯一执行定义，不是第二个控制器。

## 轻量前置

单 Session 在时间盒内预演失败原因、缓解动作和责任人。低风险、对象不清或协调净收益不正时只用本分支，不启动多 Agent。

## 重型进入门

只用于产品决定、长期边界或共享架构。攻击对象必须已经写成明确的问题定义、方案或合同，且选错的预期损失高于多 Session 协调成本；对象不清先返回 P1。已有多 Agent 委派、写入所有权和成本上限不因本协议扩张授权。

`orchestrated-collaboration` 的 `references/collaboration-shapes/cf-5.md` 只提供角色拓扑、所有权和交付适配；本文件独占轮次、评论、裁决与停止规则。

## 两轮协议

推进单位是**轮**。标准两轮：第一轮至少两个独立攻击视角，第二轮至少两个未参与者交叉裁决，因此下限为四个独立 Agent／Session；第二轮只形成候选，不实施。

| 构件 | 可执行要求 |
| --- | --- |
| 角色分区 | 按真实攻击面枚举至少两个视角，每个视角一个独立 Session，不在同一上下文里自我红队 |
| 每人一条自足评论 | 每个执行者只发布一条带轮次与角色标识的评论，另一个 Session 不读派发上下文也能复核 |
| 必答结构 | 最可能错误的三点／推荐方案／最强反方／失效条件／需要实验的未知／MVP 必须具备与明确不做 |
| 事实推断分开 | 引用来源与自身推断逐条分开标注，二手转述注明未核验 |
| 上限时间 | 每轮设时间盒，到点收口，不追求穷尽 |
| 交叉裁决 | 一人检查组合、自相矛盾和状态遗漏；一人从“尽量不自建、降低判断税”立场攻击整套方案 |

命中任一即停止：两轮完成；时间盒用尽；新一轮不再产生会改变决定的新攻击；对象被证伪而需返回 P1。独立上下文、真实不同视角和外部证据不可由同一上下文自审替代。

若已登记 Agent 系统迭代事件且需要跨 Session 恢复裁决，按需加载 `self-improvement` 的 `references/iteration-receipt.md`，只把增量证据交给当前回执唯一写入者。第一轮发现仍是候选，不产生实施权。
