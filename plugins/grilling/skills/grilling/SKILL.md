# Grilling

通过结构化追问检验用户的想法，直到双方形成清楚的共同理解。在内部把问题看成一棵决定树：每个已经确定的决定，都可能展开出依赖它的后续决定。

## 先确认是否得到同意

只有在对话中已经明确出现以下任一情况时，才可以开始提问：

- 用户直接要求使用 `grilling`、盘问或结构化压力测试；
- 用户明确接受了此前使用本方法的建议。

任务很复杂、出现了相关关键词，或者 Agent 自己认为方法有用，都不算用户已经同意。如果本 Skill 在没有上述同意时被加载，不得直接展开问题。最多只提出一次简短建议，并同时说明：

- 观察到了什么新的不确定性或风险；
- 它可能怎样改变结果；
- 本方法可能帮助澄清什么；
- 会增加多少提问或调查成本；
- 用户也可以继续走普通任务路径。

然后等待用户选择。如果用户选择普通路径，就继续普通任务；不得因为同一个理由换一种说法再次建议本方法。只有新证据实质改变了风险、成本、范围或可能结果时，才能再次建议，并说明这次与上次相比发生了什么变化。

## 沿决定树逐轮推进

按轮次推进。每轮开始前，找出所有“前置决定已经确定、现在就能回答”的未决问题。相互独立的问题可以放在同一轮；依赖另一个未决答案的问题必须延后。

每个问题都要清楚编号，并跟随用户使用的语言。优先使用普通词，必要的专业词要随手解释。采用下面的格式：

```text
Q1 · 简短标题

问题正文；只有确实有帮助时，才给少量互不重叠的选项。

建议答案：Agent 的建议及其主要理由。
```

得到用户回答后，才能展开依赖这些答案的分支。每个回答都可能确定、删除或新增分支，因此每轮结束后都要重新计算当前可以回答的问题。普通说法已经足够清楚时，不要向用户暴露 `frontier` 等内部方法术语。

## 把事实和决定分开

查明事实是 Agent 的工作。根据当前环境和成本，使用已有上下文、仓库文件、可用工具、官方来源，或者在确实值得时使用子 Agent。不要强制委派，也不要把能够安全、适度查明的事实反过来询问用户。

一个尚未查明的事实，只应推迟依赖它的决定；其他已经可以回答的问题仍可继续。价值选择、偏好、范围边界和取舍仍由用户决定；Agent 要给出建议，然后等待用户选择。

## 控制成本并允许退出

提问规模必须与决定的重要性相称。如果剩余问题的预期价值很低、调查成本太高、问题已经足够清楚，或者本方法并不适合，就应建议停止或改用其他路径。

用户随时可以选择普通任务路径、换一种方法或停止。降级或退出时，停止剩余问题，并交接：

- 原始任务；
- 已经确认的决定；
- 仍未知的事实或假设；
- 接下来选择的路径。

不要让用户重复已经确认的信息。

## 实施前再次确认

当约定范围内不再有重要的未决分支时，提问过程结束。用人话总结共同理解，包括所选方向、重要但未选择的替代方案、剩余未知，以及仍需补充的证据。

请用户确认这份总结。在得到确认前，不得实施依赖这些决定的工作。确认后，把原任务、决定和未知项交回正常工作流，使实施可以继续而不丢失上下文。
