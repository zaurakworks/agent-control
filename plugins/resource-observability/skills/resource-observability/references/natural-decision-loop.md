# 自然资源决定闭环

本 reference 只在一个已经值得推进、已有授权且资源信息可能改变选择的高成本／多 Agent 自然事件处使用。它用一次“事前反事实＋成对账户快照＋实际 Session 回执＋决定结果”检验资源数据有没有改善投入决定；不为实验制造任务，不建设轮询、监控、历史序列、自动派发或自动停止。

## 一、进入与停止

同时满足才进入：

- 即使没有临期额度，这项工作也值得完成，并且已有任务合同与排他写入所有权；
- 当前确实要在加派、维持、停止新增或延后之间作出选择，资源信息可能改变选择或排除一个错误理由；
- 开始与决定点都能读取同一 Provider、同一窗口且 `updatedAt` 时间前进的账户快照；
- 实际参与者的 Session ID 可取得，协调者能记录队列、所有权、验收容量、返工和负责人打扰。

没有自然决策点、窗口不可比，或预计／实际记录时间超过 5 分钟时停止，不补造样本。账户层或会话层探针出现协议／版本错误、Token 不守恒或目标安装版本不一致时，停止本闭环并把可靠性缺口交回当前任务；不要用不可信读数继续作资源归因。

## 二、事前登记

读取资源数据以前写下：

1. 当前任务、自然事件和需要作出的选择；
2. **无资源数据时会怎样决定**，以及已有的价值、依赖、所有权、验收容量和风险理由；
3. 哪项资源信号可能翻转选择，哪些未知值会撤销“基于额度”的理由；
4. 本次最多记录 5 分钟，窗口不一致、采集时间不前进或无法归因即停止。

这份登记固定事前反事实，不因看到结果而改写。资源只作约束或同价值候选间的加速条件；它不把低价值、未授权或不可验收的工作升级成任务。

## 三、取得成对快照与会话回执

1. **开始快照**：在事件开始处按主 Skill 的账户层规则读取一次，只保留脱敏后的 Provider、窗口身份、已用／派生剩余、重置时刻、`updatedAt`、来源、状态和未知值。
2. **决定点快照**：作出投入选择前再读一次。只有 Provider 与窗口相同、来源正常且 `updatedAt` 确实前进，才比较读数；否则把跨时点变化记为未知，只撤销资源扩产理由，不停止由价值、合同与所有权支持的工作。
3. **实际 Session 回执**：事件结束后，为每个实际参与 Session 运行一次主 Skill 的 `resource-observability.session/v1` 入口。未参与的 Session 不为形式生成回执；账户还有其他活动而无法把差值归因到这些 Session 时，明确保留未知，不推断燃烧速度。

不得保存原始账户响应、账户标识、凭据、日志路径或上游错误正文。动态快照只进入当前任务的实验／交付证据，不进入权威或长期知识。

## 四、写一份自足结果回执

在当前任务已经指定的持久审阅面写一份回执，使新 Session 不读聊天也能复核：

- **事前反事实**：无资源数据时的原决定、理由和可能翻转它的信号；
- **观测事实**：两次脱敏账户快照、可比性结论、每个实际参与 Session 的回执身份，以及所有失败与未知；
- **实际决定**：加派、维持、停止新增或延后中的哪一项，资源数据是否改变决定，或未知值是否正确阻止了错误理由；
- **结果**：稳定交付与验收情况、失败／重试、写入碰撞、返工、验收容量、负责人打扰，以及这些结果能否归因于本次选择；
- **成本与副作用**：总记录时间、范围外影响、未运行项和剩余验证缺口；
- **结论边界**：本次最多形成一个自然波次样本。正结论、负结论或“仍未知”都可完成本闭环；不得据此声称产品采用、长期依赖或自动化授权。

闭环完成只证明另一个执行者可以复核“资源数据是否改变了真实决定，以及该决定连到了什么结果”。它不要求资源信号必须改变选择，也不以 Token 消耗、并发数量或任务数量代替有用结果。
