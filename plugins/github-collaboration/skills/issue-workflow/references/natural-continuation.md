# 自然续接的准入、限流与退出

只在在线 Session 于**任务完成、工具／环境失败或可复用纠偏**处，自然暴露一个能从当前合同、刚产生的证据或有效来源链定位到具体父 Issue 的缺口时读取。本文不是队列扫描器；普通明确任务仍按原合同结束。

## 恢复明确父级

只能从当前任务合同、刚产生的证据或已经有效的来源链定位一个具体父 Issue；重新读取它的远端状态、实施授权、未满足成功条件、原生子项与依赖，以及当前活动 Session／Delivery 的写入所有权。若同一父级已有仍在线的驱动者，保持只读加入现有协调并取得明确分区，不并起第二个驱动者。**没有明确、OPEN 的父 Issue 时退出，不扫描仓库队列寻找一个父级。**

没有明确父级、只有低影响一次性细节、没有开放父级，或观察与父级未满足成功条件无直接关系时，直接退出，不为了“续航”强行找活。

## 把观察分为四类，而不是机械建 Issue

- **退出**：普通任务已经完整结束、只是低影响一次性细节、没有开放父级，或与父级未满足成功条件无直接关系；
- **只记录摩擦／证据**：观察值得保留，但还不能写成可交付目标或没有达到当前父级的行动门；
- **形成候选**：可能值得处理，但仍缺下面某项准入、需要产品取舍或需要负责人专属决定；
- **形成可执行子 Issue**：下面七项准入全部成立，且没有命中限流。

## 可执行子 Issue 的全部准入条件必须同时成立

七项必须同时成立：

1. 当前存在明确、**OPEN 且实施授权仍有效**的父 Issue；
2. 缺口直接对应父级一条**未满足成功条件**；
3. 目标、验收、成本上限、停止条件和交付位置都能从现有证据写清；
4. 不改变产品边界、长期依赖、风险偏好或负责人专属决定；
5. 首个动作只读或容易回退，不自动合并、安装、删除或修改宿主环境；
6. 写入所有权排他，没有活动 Session／Delivery 冲突；
7. 没有未解除依赖，且这次临时恢复父级、形成可交付合同的协调净收益为正；是否把执行交给另一个 Session，仍由核心第六节的现有派发门判断。

## 先读远端再限流

每个自然事件进入本路径的一次恢复最多形成 **1 个新子 Issue**；同一父级最多同时存在 **2 个由本机制自动派发的活动子项**。计数使用父级原生子图、子项合同和当前活动派发事实，不建立另一套登记表；无法可靠确认计数时按限流不成立处理。第一阶段只自动派发只读诊断或容易回退的任务。

**任一准入或限流条件不成立时，只退出、记录摩擦／证据、保留候选或合并成一次负责人决定，不派发。**

## 复用现有段行为

准入通过后由 `objective-to-issues` 在现有授权内建立或复用原生子 Issue；凡新建 Issue 都统一应用其第三节共享创建骨架，本节不复制标题、label、正文、关系、Project、建图、去重或 GitHub 写入细节。随后回到第六节第 5 步，决定由当前发现者自己执行，还是通过 `orchestrated-collaboration` 与当前真实后端派发；本节不保存任何协调后端命令。建立 Issue 或开始派发都**不等于授权合并、安装、删除、修改宿主环境或其他破坏性动作**。

## 发现者回写后退出

发现者把分类、子 Issue／候选、派发或不派发理由、结果和仍未满足条件写回父级，然后退出这次局部驱动职责，不保留永久协调者身份。后续生命周期仍只由 `issue-workflow` 在新的远端事实下继续，经营总账和各段 Skill 不复制这套分类或完成判定。
