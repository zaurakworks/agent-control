# 知识维护

目标是让后续任务直接复用仍成立的成果，只调查已经变化、发生冲突或仍然缺失的部分，并使维护成本低于重复调研。

当前知识只包含可信、仍适用、容易理解、足以复用的结论与必要内容。保存原始材料不等于形成知识；不要创建“低可信知识”或“待验证知识”等中间知识状态。

## 一、确认本次是否应使用

出现以下任一情况时使用本流程：

- 准备进行多来源调研；
- 准备运行以后可以重复的实验；
- 结果将影响当前权威、Agent 配置或重要决定；
- 用户明确要求复用、复核、更新或保存当前知识；
- 已有当前知识可能失效、互相冲突或缺少本次适用范围。

以下情况直接按普通任务处理：

- 低成本、一次性、不会形成重要决定的事实查询；
- 只需要保存会话、工具输出、失败实验、假设或其他原始证据；
- 只因为一次调研已经很贵，就想把所有结果长期保存；
- 计划定时重做全部调研或整体导入旧仓；
- 正在设计尚未确认边界的私域知识系统。

若任务同时包含普通工作和知识维护，只对需要复用或更新的窄问题运行本流程，不把整个任务升级成知识工程。

## 二、界定一个窄问题

先写清：

- 当前要回答的问题；
- 对象、版本、环境和时间范围；
- 哪个决定或后续任务会使用答案；
- 本次停止条件。

不要先决定仓库、目录、数据库或知识图谱。只有当前权威已经认可某个知识入口时，才把它视为“当前知识”。旧仓、旧 Issue、历史版本、研发记忆和任务证据只是待核验来源。

## 三、先找当前知识并做最少复核

1. 从当前任务或权威明确指出的知识入口寻找范围匹配的知识包；不要默认遍历所有历史材料。
2. 逐条检查核验时间、对象、版本、环境、例外和失效条件。
3. 按知识中写明的“下次最少复核步骤”确认结论是否仍成立。
4. 无法用最少步骤确认的结论立即退出当前知识；重新核验前只能作为历史证据，不能直接使用。不要因为内容已保存就继续引用。
5. 没有认可的当前知识入口时，记录这是缺口，继续形成候选，但不要擅自发明新的知识平台或把候选称为当前知识。

## 四、只列变化、冲突和缺口

把现有内容分成四类：

- 仍成立且可直接复用；
- 已发生变化；
- 来源或结论互相冲突；
- 当前知识没有覆盖。

只对后三类进行增量调研或实验。已经通过最少复核的结论不重新做完整调研。优先使用第一方来源或别人可以重复的验证过程；确实需要独立复核时再增加 Agent 或实验，不为形式完整制造无价值工作。

## 五、逐条通过两道准入门

知识包是容器，每条可复用结论独立判断。

### 价值门

至少满足一项：

- 后续任务较可能再次使用；
- 正在更新或替换现有知识；
- 需要长期解释一个重要决定。

已经投入很多时间不是长期维护的充分理由。

### 可信门

每条结论必须同时具备：

1. 明确回答的问题；
2. 可以直接使用的结论和必要解释；
3. 第一方来源或别人可以重复的验证过程；
4. 对象、版本、环境和核验时间；
5. 例外、仍未知内容和不能推出的结论；
6. 明确的失效条件；
7. 下次最少复核步骤；
8. 人容易理解、Agent 足以复用的表达。

“目前不知道”可以成为结论，但必须说明已经核验的范围和依据。猜测、未完成的方案和只与成功同时出现的做法不能通过可信门。

## 六、按结果路由

- 两道门都通过：当前任务已授权维护该知识入口时，直接更新或替换对应结论；否则输出可审查的知识候选和所需授权。
- 价值门未通过：保留在任务证据中，不进入知识。
- 可信门未通过：保留在研发记忆或证据中，明确缺失项，不进入知识。
- 旧结论已经失效：从当前知识中退出；Git 历史可以保留过去版本，但过去版本不再代表当前答案。
- 来源难以再次取得，或复核依赖精确原文、配置或实验输入：只保存必要的本地副本；其他情况保留来源和复核步骤即可。

出现证据直接冲突、将改变权威或重要决定、证据不足却必须行动、涉及私域或高损失风险时，增加独立 Agent 或请求负责人决定。不要让知识写入绕过原本需要的授权。

## 七、交付可复查结果

输出至少包括：

- 本次窄问题和适用范围；
- 找到并直接复用的当前结论；
- 变化、冲突和缺口；
- 增量核验的来源或可重复步骤；
- 每条候选的价值门、可信门判断；
- 已更新的知识入口，或未写入时的去向与原因；
- 仍未知内容、失效条件和下次最少复核步骤。

只在自然任务中、数据容易取得时附带记录：是否找到知识、复用了什么、补查了什么、可见的近似时间或 Token、负责人纠正和维护额外工作。不要为了计算投入产出而重跑完整调研，也不要编造不可见数据。

当本次知识维护来自已经登记的 Agent 系统迭代事件，并且需要跨 Session 恢复知识出口时，按需加载 `self-improvement`，读取其 `references/iteration-receipt.md`，只把本流程实际产生的证据等级、稳定落点、失效条件和最少复核步骤交给当前回执的唯一写入者。这项引用不调用自我改进、不建立第二个知识状态；本 Skill 的价值门与可信门仍是知识准入的唯一判断。
